# Topo v1.1.7

Topo v1.1.7 is a security-boundary and result-integrity release. It removes unsafe system-wide entry points into user-writable installations, moves the curl installer to a signed release asset, and eliminates whole-application passwordless sudo authorization. Cleanup and optimization commands now report partial failures accurately, while additional safeguards keep previews, deletion accounting, and recoverable application data aligned with what Topo actually does.

---

## Highlights

### 1. Safer Installation and Update Trust Boundaries
- User installations no longer offer or create a `/usr/local/bin/topo` fallback that points into the user-writable `~/.topo` tree. The launcher remains under the user's configured link directory, normally `~/.local/bin`.
- Releases now publish `install.sh` as a signed, checksummed asset alongside the source archive, engines, and packages.
- The documented curl installation command uses the versioned latest-release asset instead of executing the mutable script from the `main` branch.
- Script updates download and verify the release installer before execution, preserving the existing GPG fingerprint and SHA-256 trust chain from bootstrap through payload activation.

### 2. Narrower Sudo Authorization Surface
- Removed the `topo authorize` command and its whole-executable `NOPASSWD` sudoers generator.
- Topo no longer recommends granting every current and future subcommand passwordless root execution through a single Python entry point.
- Operations that genuinely need administrator access continue to request sudo at the individual command boundary; normal user-space scanning, previews, and selection remain unprivileged.
- Existing administrator-managed sudoers files are left untouched rather than being deleted or rewritten automatically.

### 3. Accurate Optimization and Partial-Failure Results
- Optimization tasks now have explicit success, visible-skip, silent-skip, and failure outcomes instead of overloading `None` for both “nothing to do” and command failure.
- Journal vacuum, Flatpak repair, cache/database refreshes, systemd maintenance, swap handling, repository refreshes, and other command-backed tasks now propagate nonzero exits and timeouts.
- Independent optimization tasks still run to completion, but any failed task produces a “completed with errors” summary and a nonzero CLI exit status.
- Package-based `topo remove` now distinguishes an absent residue from successful and failed cleanup attempts. If the package is removed but user residue cleanup is incomplete, Topo reports the partial completion and returns failure without pretending the package transaction was rolled back.

### 4. More Truthful and Recoverable Cleanup
- Zombie cleanup signals each eligible parent PID only once, counts only successful signals, and reports failed or non-actionable entries separately. Dry-run output no longer claims work was completed.
- Cleanup previews now follow the same filters and safety decisions as execution, reducing differences between what Topo presents and what it can remove.
- Trash-backed cleanup separates bytes moved to Trash from space immediately freed, so reclaim totals no longer imply that recoverable files released disk space at once.
- Protected application data and transient targets are kept when removal would be unsafe or irrecoverable; explicit rejection reasons are shown instead of collapsing distinct failures into a generic result.

### 5. Clearer Internal Contracts and UI Accounting
- Analyze scan records and cache invariants use checked types and centralized helpers, reducing implicit state shared between scanning and navigation.
- Cleaner totals, item breakdowns, icon padding, text rendering, whitelist handling, and scan-cache behavior now have single owners instead of repeated local calculations.
- Obsolete dry-run reporting code was removed after preview generation moved to the cleaner results that execution already uses.
- Regression coverage now includes installer trust boundaries, permanent-versus-recoverable removal policy, result aggregation, parent-process deduplication, package residue failures, and environment-independent database refresh tests.

---

## Verification
- The Python suite contains 1,011 tests and runs on Python 3.10 and 3.14 in CI.
- CI enforces Ruff linting and formatting, Mypy including untyped function bodies, Tach module boundaries, Vulture dead-code checks, ShellCheck, Cargo Clippy/formatting, and Rust unit tests.
- Release jobs build x86_64 and aarch64 static musl engines plus DEB and RPM packages, then smoke-test script installation, package installation/removal, multiple Linux distributions, and ARM64 execution under QEMU.
- Every published installer, source archive, engine, and package is covered by `SHA256SUMS`; the manifest is signed with the project release key before the GitHub Release is created.

# Topo v1.1.7 中文发布说明

Topo v1.1.7 重点收紧安全边界并修正结果完整性：移除指向普通用户可写安装树的不安全系统入口，将 curl 安装入口迁移到签名 Release 资产，并删除整套应用免密 sudo 授权。清理和优化命令现在能够准确报告部分失败；同时，预览、删除计数和可恢复应用数据的保护语义也与实际执行保持一致。

---

## 主要更新

### 1. 更安全的安装与更新信任边界
- 用户安装不再提供或创建指向 `~/.topo` 可写代码树的 `/usr/local/bin/topo` fallback；launcher 保持在用户配置的链接目录中，默认是 `~/.local/bin`。
- Release 现在会将 `install.sh` 与源码归档、engine 和系统包一起作为经过签名清单覆盖的资产发布。
- 文档中的 curl 安装命令改用版本化的 latest-release 资产，不再直接执行 `main` 分支上可变的安装脚本。
- 脚本更新会先下载并验证 Release installer，再开始执行；既有固定 GPG 指纹与 SHA-256 信任链从 bootstrap 延伸到载荷激活阶段。

### 2. 更窄的 sudo 授权面
- 删除 `topo authorize` 命令及其 whole-executable `NOPASSWD` sudoers 生成器。
- Topo 不再建议通过单个 Python 入口，为当前及未来所有子命令授予免密 root 执行能力。
- 确实需要管理员权限的操作继续在具体系统命令边界请求 sudo；普通用户空间扫描、预览和选择仍保持无特权。
- 已由管理员维护的 sudoers 文件不会被程序自动删除或重写。

### 3. 准确的优化与部分失败结果
- 优化任务现在显式区分成功、可见跳过、静默跳过和失败，不再让 `None` 同时表达“无需执行”和命令失败。
- Journal vacuum、Flatpak repair、缓存和数据库刷新、systemd 维护、swap、软件源刷新及其他命令型任务现在会传播非零退出与超时。
- 单个优化失败不会阻止其他独立任务运行，但最终会显示“completed with errors”，CLI 也会返回非零状态。
- 包安装来源的 `topo remove` 现在能区分残留不存在、清理成功和清理失败。若软件包已移除但用户残留清理不完整，Topo 会明确报告部分完成并返回失败，同时不会暗示包事务已回滚。

### 4. 更真实且可恢复的清理
- Zombie 清理只对每个符合条件的父 PID 发送一次信号，只统计成功的 signal，并分别报告失败与不可操作项；dry-run 不再声称已完成操作。
- 清理预览与实际执行共用相同的过滤和安全判断，减少“预览显示可清理、执行时却不能处理”的差异。
- 使用回收站的清理会将“移入回收站的字节”与“立即释放的空间”分开统计，不再把可恢复文件误算为已经释放磁盘空间。
- 当删除可能不安全或不可恢复时，受保护应用数据与临时目标会被保留；终端显示具体拒绝原因，而不是将不同失败折叠为通用结果。

### 5. 更清晰的内部契约与界面计数
- Analyze 扫描记录与缓存约束改用可检查类型和集中 helper，减少扫描与导航之间的隐式共享状态。
- Cleaner 汇总、项目明细、图标 padding、文字渲染、whitelist 和扫描缓存的计算进一步收敛到单一实现位置。
- 预览生成改为使用执行流程已有的 cleaner result 后，旧的 dry-run reporter 已删除。
- 回归测试新增安装信任边界、永久删除与可恢复删除策略、结果聚合、父进程去重、包残留失败以及不依赖本机 HOME 的数据库刷新场景。
