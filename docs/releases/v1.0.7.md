# Topo v1.0.7

Topo v1.0.7 is a major release focusing on **Terminal UI & Alignment Correctness**, **Performance & Algorithmic Scalability ($O(E+D)$ tree scans, $O(A \times T \times \text{subset})$ residue indexes, $O(K \log K)$ purge deduplication)**, and a **Comprehensive System Health Dashboard Overhaul**.

---

## Highlights

### 1. Performance & Algorithmic Optimizations
- **Rust Core Tree Aggregation ($O(F \times D) \to O(E+D)$)**:
  - Replaced repetitive ancestor lookups with a high-performance **Bottom-Up Topological Folding** algorithm. Files accumulate directly to immediate parents during traversal and aggregate once upward per directory level, eliminating massive hashmap lock and string splitting contention in deep directory trees.
  - Modularized `topo-core` into `lib.rs`, `scanner.rs`, and lightweight CLI binary.
- **Python App Residue Matching Optimization (`app_manager.py`)**:
  - Introduced `_ResidueEntryIndex` using exact maps, 3-character prefixes, and a 2048-bucket 5-gram hash index backed by contiguous C-memory `array("I")`.
  - Reduced residue matching complexity from $O(A \times T \times N)$ to candidate subsets while preserving full `_name_matches()` rule verification.
- **Project Artifact Deduplication Optimization (`project.py`)**:
  - Decoupled discovery from canonical deduplication, eliminating quadratic nested checks ($O(K^2) \to O(K \log K)$).
- **Rust-Provided Memory Cache Estimation (`scan_cache.py`)**:
  - Leveraged Rust-native precise memory estimation structures to avoid redundant cache calculations.

### 2. System Health Status Dashboard Overhaul (`topo status`)
- **Visual Streamlining & Noise Reduction**:
  - Clarified Uptime with `(since boot)` suffix (e.g. `13h 45m (since boot)`).
  - Removed redundant Swap and ZRAM display rows and purged dead code.
  - Simplified CPU metrics by replacing raw `1m, 5m, 15m` load averages with a clean `load X%` unit.
  - Aligned compute metrics into a compact, symmetrical layout: `📟 CPU Status:` and `🎮 GPU Status:`.
- **Authentic Hardware Sensor Detection & Multi-Tier Fallbacks**:
  - **CPU Temperature**: Strictly prioritized dedicated CPU hardware drivers (`coretemp` on Intel, `k10temp`/`zenpower` on AMD, `cpu_thermal` on ARM) reading authentic Die/Tctl/Package sensors with sentinel value filtering ($0 < T < 125^\circ\text{C}$).
  - **GPU Decoupled Probing**: Decoupled DRM GPU temperature and utilization probing. Accurately reports standalone temperature or utilization when only one node is present, prioritizes junction/hotspot peak sensors, and eliminates fake `load 0%` artifacts.
  - **Physical Network Traffic Denoising**: Prioritizes interfaces with `/sys/class/net/<iface>/device` hardware links while blacklisting Docker, veth, bridge, WireGuard, and Tailscale virtual interfaces. Added seamless default-route fallback for containers and PPP links.
- **Overall System Health Assessment**:
  - Added an intelligent, 3-tier health assessment verdict printed at the bottom:
    - `🌿 System is running in optimal condition.`
    - `🟡 System status is moderate (...)`
    - `🔴 System under heavy load: (...)`

### 3. Terminal UI, Alignment & Color Correctness
- **One Single Character-Width Model (`core.text`)**:
  - Centralized `char_width()` and `display_width()` as the single source of truth across all reports and selectors. Variation selectors (U+FE00–U+FE0F) count as 0 cells, properly handling composite glyphs like U+23F1.
  - Standardized `show_status()` row rendering via measured padding in `_status_row(icon, label, value)`.
- **Deletion Confirmation Readable Without Color**:
  - Armed buttons now render as `▸ Yes ◂` / `▸ No ◂` against `  Yes  ` / `  No  `, ensuring shape carries state under `--no-color` or piped execution.
- **Adaptive Palette-Responsive Theme Colors**:
  - Restored `EARTH` branding color on the TUI banner mapped to adaptive ANSI `YELLOW` (`\033[1;33m`), ensuring high contrast across dark, light, Solarized, and Nord palettes.
  - Fixed status dot color churn on keystroke redraws by linking it directly to constants.
- **Numeric Main Menu Navigation & Responsive Selectors**:
  - Main menu responds directly to digit keys (`1`–`5`).
  - Improved interactive responsiveness and dynamic terminal resizing in uninstall and clean selectors.
  - Applied `<0.1%` lower bound formatting uniformly to avoid confusing `0.0%` rendering for active resources.

## Verification

# Topo v1.0.7 中文发布说明

Topo v1.0.7 是一个重大更新版本，重点聚焦于 **终端 UI 与字符对齐正确性**、**核心算法与海量数据扫描性能优化（$O(E+D)$ 树折叠、残留索引过滤、产物去重）** 以及 **系统健康面板（System Health Status）的全面视觉与硬件探测重构**。

---

## 核心亮点

### 1. 核心性能与算法复杂度优化
- **Rust 核心目录树扫描折叠优化（$O(F \times D) \to O(E+D)$）**：
  - 将原先深层路径中重复向上遍历祖先的机制重构为**自底向上拓扑折叠算法（Bottom-Up Topological Folding）**。遍历时仅将文件大小累加至直接父目录，按深度逆序向上单次折叠，彻底消除了超深目录下频繁字符串分割与哈希表写锁开销。
  - 将 `topo-core` 模块化重构为 `lib.rs`、`scanner.rs` 及轻量二进制入口。
- **Python 应用残留扫描索引优化（`app_manager.py`）**：
  - 引入 `_ResidueEntryIndex` 紧凑候选索引，由精确表、3 字符前缀表及 2048 桶 5-gram 哈希索引构成，底层采用紧凑 C 内存 `array("I")`。
  - 残留扫描复杂度由 $O(A \times T \times N)$ 降至极小候选子集，同时百分之百保持 `_name_matches()` 规则校验精度。
- **构建产物去重算法优化（`project.py`）**：
  - 将产物收集与路径规范化归并解耦，消除了嵌套扫描时的平方阶复杂度（$O(K^2) \to O(K \log K)$）。
- **Rust 原生内存缓存估算（`scan_cache.py`）**：
  - 接入 Rust 核心引擎提供的高精度内存估算接口，优化缓存计算开销。

### 2. 系统健康状态面板全面重构（`topo status`）
- **界面精简与信息去噪**：
  - 开机运行时间（Uptime）添加 `(since boot)` 明确注释（如 `13h 45m (since boot)`）。
  - 移除常年 0% 且概念重复的 Swap 与 ZRAM 状态行，清理相关死代码。
  - CPU 负载去噪：移除晦涩的 `1m, 5m, 15m` 平均数，统一为带单位的 `load X%`。
  - 格式统一规范：`📟 CPU Status:` 与 `🎮 GPU Status:` 形成严格对称的 `温度 | load 利用率%` 极简视觉结构。
- **真实核心硬件传感器探测与多级 Fallback**：
  - **CPU 核心温度**：优先直读专用 CPU 硬件驱动（Intel `coretemp`、AMD `k10temp`/`zenpower`、ARM `cpu_thermal`）的真实 Die/Tctl/Package 核心发热点，增加 $0 < T < 125^\circ\text{C}$ 异常哨兵过滤。
  - **GPU 解耦独立探测**：解耦 DRM GPU 温度与利用率探测，支持单温度、单利用率独立展示，优先捕获结温（Junction/Hotspot）热点，避免伪造 `load 0%`。
  - **物理网卡流量去噪**：优先统计具备 `/sys/class/net/<iface>/device` 硬件节点的网卡流量，排除 Docker、veth、桥接、Tailscale/WireGuard 等虚拟网卡干扰；容器与 PPP 拨号环境自动平滑回退至默认路由。
- **智能系统健康度结论评估**：
  - 面板底部新增严格左对齐的 3 档状态结论徽章：
    - `🌿 System is running in optimal condition.`（系统运行状态极佳）
    - `🟡 System status is moderate (...)`（系统状态良好/中等负载）
    - `🔴 System under heavy load: (...)`（系统高负载/瓶颈告警）

### 3. 终端 UI、字符宽度与配色自适应
- **统一的字符显示宽度模型（`core.text`）**：
  - 在 `core.text` 中集中实现 `char_width()` 与 `display_width()`，精准识别变体选择符（U+FE00–U+FE0F）为零宽，彻底解决 Emoji 及复合符号在终端中的对齐错位问题。
  - `show_status()` 统一经由自适应槽宽计算的 `_status_row(icon, label, value)` 渲染。
- **无色环境下删除确认框无障碍可读**：
  - 确认按钮改为 `▸ Yes ◂` / `▸ No ◂` 字形标记，确保在 `--no-color`、`NO_COLOR` 或管道输出下仍能清晰辨识选择状态。
- **终端调色板自适应高亮**：
  - 恢复 `EARTH` 大地色 Banner 并映射为标准 ANSI `YELLOW`（`\033[1;33m`），彻底告别固定 256 色在某些深色/浅色调色板下对比度偏低的问题。
  - 修复状态小圆点在按键重绘时抖动变色的问题，统一绑定常量。
- **主菜单数字键快速响应与响应式选择器**：
  - 主菜单支持按键 `1`–`5` 直接激活对应功能。
  - 卸载与清理选择器全面支持窗口动态尺寸自适应。
  - 百分比统一应用 `<0.1%` 下限格式化，避免微小占用被粗暴截断为 `0.0%`。
