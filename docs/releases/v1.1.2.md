# Topo v1.1.2

Topo v1.1.2 is primarily an architectural refactor: it establishes explicit command boundaries, removes the former core-to-UI dependency cycle, and puts the module contract under automated enforcement. On top of that foundation, Analyze receives clearer file-type cues and more predictable multi-page selection.

---

## Highlights

### 1. Architectural Refactor and Module Boundaries
- Split top-level commands by what they act on: Analyze, Uninstall, Optimize and Status became feature modules of their own, and `doctor` moved in beside the installation lifecycle commands under `src.manage`, since it diagnoses the Topo installation rather than the user's system.
- Moved the interactive Analyze and Uninstall flows into `src.ui.screens`, eliminating the former `core -> ui` dependency cycle.
- Extracted shared infrastructure into focused core modules, including the Rust engine interface, notification sounds, rendering helpers, and file-type classification. Two lazy imports that existed only to break an import cycle are now ordinary top-level ones.
- Reorganized system-cleaning task aggregation so each feature owns the behavior it exposes, and the cleanup summary reports every group at the same granularity.
- Brought the Tach boundary check into the repository and into CI: `tach.toml` is now tracked rather than a local-only file, and GitHub Actions enforces it alongside the existing local `check.sh` run.

### 2. File-Type-Aware Analyze Rows
- Analyze now assigns recognizable icons to common file categories, including audio, video, images, disk images, archives/packages, documents, and source code.
- File classification uses a deterministic extension table rather than MIME probing, avoiding per-row subprocesses or file-content reads during navigation.
- Directory detection remains authoritative, and unknown or extensionless files continue to use the standard file icon.
- Icon width and spacing are normalized across Analyze rows and selected-file summaries to preserve alignment across terminal widths.

### 3. More Predictable Analyze Selection
- Fixed numeric selection so `0` is no longer interpreted as item 10; row 10 is reached by typing `10`.
- Analyze and Uninstall now resolve a typed row number through the same code path, so the two screens cannot drift apart in how a displayed number maps to an entry.
- Fixed Analyze's row-number column, which was a fixed two cells. A preview-mode listing is not capped at 50 rows, so three-digit numbers pushed every later page one column to the right; the column is now sized from the full list.
- Selected rows keep their purple marking while the cursor passes over them, instead of turning cyan and hiding what was about to be deleted.
- Fixed `--no-color`: list rows, the main menu and the uninstall preview emitted raw ANSI escapes that the colour switch could not reach, so they stayed coloured under `--no-color`, `NO_COLOR` and in piped output.
- Selected large-file summaries adapt to the terminal width and keep paired entries aligned.

### 4. Consistent Pagination and Screen Layout
- Uninstall row numbering now continues across pages instead of restarting on each page.
- Fixed Uninstall digit selection, which read the typed digits as a position *within* the page and added the page origin, so `20` typed on page 1 selected a row on page 2. Numbers now address only the rows on the page in view.
- Replaced the "More items above / below" pair with a single ellipsis beneath the row numbers, shared by both screens. The selection hint moved out of the footer, which had grown past 80 columns and was truncating that hint away first, into a sentence under the title.
- Screen titles, counters, sizes, and selection indicators were aligned and color-grouped for faster scanning.

### 5. Cleaner Quality Gates
- Aligned the CI `pytest` and Mypy invocations with the local `check.sh` gate; CI had been running Mypy without `--check-untyped-defs`, making it strictly weaker than the local check.
- Moved the Vulture ignore list into `pyproject.toml`, removing a standalone file along with the Ruff exclusion and the shell guard that existed only to support it.
- Added focused regression coverage for file-type icons, Analyze selection, pagination, color behavior, and the new module boundaries.

---

## Verification
- `tach check` passes, including `--exact`, with no unused dependency declarations.
- File-type classification tests pass across known, unknown, mixed-case, compound-extension, and directory-name cases, and assert that no extension is claimed by two categories.
- The full local gate (Ruff, Mypy, Tach, Vulture, ShellCheck, Clippy, pytest, cargo test) passes, and the Python and Rust suites remain required in CI.

# Topo v1.1.2 中文发布说明

Topo v1.1.2 以架构重构为主线：建立清晰的命令模块边界，消除原有的 Core 到 UI 反向依赖，并把模块契约交给自动化强制执行。在此基础上，Analyze 的文件类型识别和多页选择体验也得到优化。

---

## 主要更新

### 1. 模块架构重构与边界治理
- 按「对谁做事」拆分顶层命令：Analyze、Uninstall、Optimize、Status 各自独立成功能模块；`doctor` 诊断的是 Topo 自身的安装而非用户系统，因此迁入 `src.manage`，与安装生命周期命令并列。
- 将 Analyze 与 Uninstall 的交互界面迁移到 `src.ui.screens`，消除原有的 `core -> ui` 反向依赖。
- 将 Rust 引擎接口、通知音效、渲染辅助和文件类型分类等公共能力提取为专用 Core 模块；两处仅为打破循环依赖而存在的函数内延迟导入，现已还原为普通的模块级导入。
- 调整系统清理任务聚合方式，让每个功能模块维护自身暴露的行为，清理汇总中各组的粒度也随之统一。
- 将 Tach 边界检查纳入仓库与 CI：`tach.toml` 从本地文件改为随仓库分发，GitHub Actions 与本地 `check.sh` 一并强制执行。

### 2. Analyze 文件类型图标识别
- Analyze 现在会为常见文件类型显示直观图标，包括音乐、视频、图片、磁盘镜像、压缩包/安装包、文档与源代码。
- 文件分类采用确定性的扩展名映射，不进行 MIME 内容探测，避免浏览列表时逐文件启动进程或读取文件内容。
- 目录判断始终优先，未知类型及无扩展名文件继续使用通用文件图标。
- 统一不同 Emoji 的显示宽度与间距，确保 Analyze 列表和已选文件摘要在不同终端宽度下保持对齐。

### 3. 更可靠的 Analyze 选择交互
- 修复数字 `0` 被错误识别为第 10 项的问题；选中第 10 项需完整输入 `10`。
- Analyze 与 Uninstall 现在通过同一段代码解析输入的行号，两个界面在「显示编号 → 实际条目」的映射上不会再各行其是。
- 修复 Analyze 行号列固定两格的问题：预览模式的列表并不受 50 行上限约束，三位数行号会把后续每一页整体右推一列；列宽现按整个列表计算。
- 已选中的行在光标经过时保持紫色标记，不再变为青色而把「即将删除的是哪些」盖住。
- 修复 `--no-color`：列表行、主菜单与卸载预览中存在颜色开关够不到的裸 ANSI 转义，导致 `--no-color`、`NO_COLOR` 及管道输出下依然带色。
- 已选大文件摘要会根据终端宽度自动调整，双列项目保持整齐对齐。

### 4. 统一分页与界面布局
- Uninstall 的项目编号现在会跨页连续累计，不再每页从头开始。
- 修复 Uninstall 的数字选择：原实现把输入的数字当作**页内**位置再加上页起点偏移，因此在第 1 页输入 `20` 会选中第 2 页的行。现在数字只指向当前页面上可见的行。
- 将「More items above / below」两条提示替换为行号正下方的单个省略号，两个界面共用同一实现。选择说明从页脚移到标题下方——页脚长度已超过 80 列，被最先截断的恰好就是这条说明。
- 对齐页面标题、数量、大小与选择状态，并通过一致的颜色分组提升扫读效率。

### 5. 更清晰的工程质量门禁
- 统一 CI 与本地 `check.sh` 的 pytest、Mypy 执行参数：此前 CI 的 Mypy 缺少 `--check-untyped-defs`，严格程度低于本地检查。
- 将 Vulture 忽略配置迁移到 `pyproject.toml`，同时移除了独立配置文件、为它而设的 Ruff 排除项，以及校验该文件存在的脚本判断。
- 为文件类型图标、Analyze 选择、分页、颜色行为及模块边界增加针对性回归测试。

---

## 验证
- `tach check` 通过，`--exact` 亦通过，无冗余的依赖声明。
- 文件类型分类覆盖已知、未知、大小写混合、复合扩展名和带扩展名目录等场景，并校验同一扩展名不会被两个类别同时登记。
- 本地完整门禁（Ruff、Mypy、Tach、Vulture、ShellCheck、Clippy、pytest、cargo test）全部通过，Python 与 Rust 测试继续作为 CI 必过项。
