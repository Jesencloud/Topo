# Topo v1.1.8

Topo v1.1.8 is a correctness and safety-hardening release. It closes the findings of an end-to-end review of every external command Topo runs and every file it removes. Uninstall and residue cleanup now recover user data through Trash before a package manager can destroy it, target the application that was actually found instead of a guessed identity, and prove process ownership before acting. Cleanup accounting reports real failures and real reclaim rather than silent zeros, command execution is pinned against locale, timeout, and argument-parsing surprises, and Topo's own state files survive concurrent writers intact.

---

## Highlights

### 1. Safer Uninstall and Residue Removal
- Snap user data (`~/snap/<app>`) is moved to Trash before `snap remove` runs, so a confined browser's bookmarks and saved logins stay recoverable — the same recovery guarantee Topo already gives Flatpak residue.
- Application selection is keyed on the on-disk record identity of the install, not a bare name or id, so a reused or duplicated identifier can no longer route removal at the wrong target.
- Removal proves that a running process actually belongs to the application before signaling it, and refuses to declare an uninstall complete while related processes survive.
- Residue that outlives its package is reported as partial success rather than a rolled-back transaction; paths derived from icon names can no longer expand into directory deletions, and paths shared across applications are skipped.
- The Pacman orphan scan runs only when its database is present and flags dependency previews it cannot resolve; Flatpak and NPM removals act on the installation and prefix actually found instead of a default guess.

### 2. Trustworthy Cleanup Accounting and Safety
- Docker and Podman prune no longer pass `--volumes`, so named data volumes are never destroyed as part of cache cleanup.
- Command-backed cleaners surface nonzero exits and timeouts as failures instead of quietly reporting zero freed bytes, and reclaim totals are read from the package manager's own reported figure rather than scraped from log text.
- Snap and DNF dry runs are true previews with no locking, no network, and no side effects.
- A superseded kernel's image, modules, and headers are purged together in a single apt transaction, while the running kernel is protected across every flavour suffix.
- Log truncation and temporary-directory removal are routed through the same whitelist protection gate as every other deletion.

### 3. More Accurate Application Discovery
- `.desktop` discovery filters hidden and non-application entries and scans the full set of XDG export directories.
- A launcher's `Exec=` line is unwrapped so a wrapper script is not mistaken for the application itself.
- Detected-application records are pinned to a directory's device and inode plus a time-to-live, so a path later reused by something else is not cleaned as stale application data.
- The scan cache expires when the package database changes, not merely when a tool appears or disappears.

### 4. Robust External Command Execution
- The synthetic return-code convention is pinned: a timeout surfaces as 124 with `timed_out`, a spawn failure as 127 with `error`, and those flags — not the numeric code alone — are the trustworthy signal of what happened.
- Commands run under a pinned C locale, terminate their arguments with `--` where the underlying parser honors it, and no longer read command silence as an affirmative answer.
- Explicit timeouts are pinned on slow maintenance tasks — fstrim, systemd-tmpfiles, coredump cleanup, Flatpak repair — and on daemon prunes, so a hung command cannot stall cleanup indefinitely.
- The output-capture contract is documented at its single source, and an unused size-parser alias was removed.

### 5. Concurrency-Safe State Files
- Whitelist read-modify-write updates are serialized with a cross-process lock, so two concurrent `topo whitelist` changes can no longer each overwrite the other and lose an entry.
- Every atomic JSON write uses its own scratch file, so two threads in one process can never publish a half-written whitelist or config.

# Topo v1.1.8 中文发布说明

Topo v1.1.8 是一次以正确性和安全加固为主的版本。它落实了对 Topo 执行的每一条外部命令、删除的每一个文件所做的端到端审查结论：卸载与残留清理会在包管理器销毁数据之前先将用户数据移入回收站以便恢复，按真实安装记录的身份而非猜测的标识来定位目标，并在操作前验证进程归属。清理计数如实报告失败与实际回收的空间，不再返回静默的零；命令执行对 locale、超时和参数解析问题做了固定处理；Topo 自身的状态文件也能在并发写入下保持完整。

---

## 主要更新

### 1. 更安全的卸载与残留清理
- Snap 用户数据（`~/snap/<app>`）会在执行 `snap remove` 之前先移入回收站，使受沙箱限制的浏览器书签与已保存登录仍可恢复——与 Topo 已为 Flatpak 残留提供的恢复保证一致。
- 应用选择以磁盘上安装记录的身份为键，而非裸名称或 id，因此被复用或重复的标识符不会再把删除操作导向错误目标。
- 删除前会验证正在运行的进程确实属于该应用才发送信号，并在相关进程仍存活时拒绝宣布卸载完成。
- 比软件包存活更久的残留会被报告为部分成功，而不是被当作已回滚的事务；由图标名派生的路径不会再扩展成目录删除，跨应用共享的路径会被跳过。
- Pacman 孤儿扫描仅在其数据库存在时运行，并标记无法解析的依赖预览；Flatpak 与 NPM 的删除会作用于实际找到的安装位置与 prefix，而非默认猜测。

### 2. 可信的清理计数与安全
- Docker 与 Podman prune 不再传 `--volumes`，因此具名数据卷不会在缓存清理中被销毁。
- 命令型清理会将非零退出与超时如实呈现为失败，而不是悄悄报告零回收字节；回收总量取自包管理器自己报告的数值，而非从日志文本中抓取。
- Snap 与 DNF 的 dry-run 是真正的预览：不加锁、不联网、无副作用。
- 被取代的内核 image、modules 与 headers 会在单个 apt 事务中一并 purge，同时正在运行的内核会在所有 flavour 后缀下受到保护。
- 日志截断与临时目录删除都经由与其它删除相同的 whitelist 保护闸门。

### 3. 更准确的应用发现
- `.desktop` 发现会过滤隐藏与非应用条目，并扫描完整的 XDG 导出目录集合。
- launcher 的 `Exec=` 会被解包，从而不会把 wrapper 脚本误当成应用本身。
- 检测到的应用记录以目录的 device、inode 加 TTL 固定，使日后被其它内容复用的路径不会被当作过期应用数据清理。
- 扫描缓存在包数据库变化时失效，而不仅仅是在工具出现或消失时。

### 4. 更稳健的外部命令执行
- 固定合成返回码约定：超时呈现为带 `timed_out` 的 124，spawn 失败呈现为带 `error` 的 127；这些标志——而非单独的数字码——才是真正可信的判据。
- 命令在固定的 C locale 下运行，在底层解析器支持时用 `--` 终止参数，并且不再把命令的沉默读作肯定回答。
- 为缓慢的维护任务（fstrim、systemd-tmpfiles、coredump 清理、Flatpak repair）和守护进程 prune 固定了显式超时，使挂起的命令无法无限期拖住清理。
- 输出捕获契约在其单一来源处有文档说明，并移除了一个未使用的 size-parser 别名。

### 5. 并发安全的状态文件
- Whitelist 的读-改-写更新由跨进程锁串行化，因此两个并发的 `topo whitelist` 变更不会再互相覆盖并丢失条目。
- 每次原子 JSON 写入都使用各自独立的临时文件，因此同一进程内的两个线程绝不会发布半写入的 whitelist 或 config。
