# Topo v1.2.0

Topo v1.2.0 is a robustness- and correctness-hardening release focused on the interactive terminal UI, packaging and update reliability, documentation accuracy, and the fidelity of the test suite. It closes the findings of two end-to-end reviews completed since v1.1.9 — a documentation ↔ implementation ↔ release consistency pass and a TUI / terminal-state restoration pass — on top of a test-coverage credibility pass. No behavior a correct run depends on has changed; what changed is what happens on the TUI's edge cases, how a package-installed topo updates, and what the README and the build actually say about themselves.

---

## Highlights

### 1. A more robust interactive UI
- The Analyze explorer no longer crashes when you press Space in an empty directory: pressing it on a view with nothing to select used to raise an `IndexError` and dump a traceback; the key is now ignored on an empty list, matching every other selector.
- The final uninstall-confirmation screen now sanitizes the application name and every residue path it draws. These were the only two render sites that passed attacker-influenceable text (a `.desktop` `Name=` field, an on-disk directory name) to the terminal unescaped, so a crafted name could inject cursor/colour control or split a line on the one screen where you confirm a deletion.
- Ctrl-C during a scan no longer leaves a stray header line in your scrollback: the spinner is now stopped before the terminal is reset, so a frame sleeping on its interval cannot repaint over the just-restored screen.
- Leaving a report (Ctrl-C, or ESC at the post-report prompt) no longer flashes a blank alternate screen on the way back to the shell — the menu only re-enters the alternate screen when it is actually going to redraw.

### 2. Dependable packaging and updates
- The DEB and RPM packages now depend on `gpg`, which `topo update` requires to verify the signed release and refuses to run without. A package-installed topo on a minimal host could previously not update, and nothing had pulled `gpg` in.
- Building a package with `--version X` now stamps that version into the runtime `VERSION` file too, so `topo --version` agrees with what dpkg/rpm reports instead of still showing the checked-out version.

### 3. Documentation that matches the program
- `topo history`'s README example now shows the real two-line-per-session output (the `started -> ended command` header and the `removed / trashed / skipped / failed` counts), captured from the actual renderer, instead of a one-line form the command never printed.
- The requirements now list openSUSE / Zypper — a first-class supported platform the install instructions had omitted — and `gpg`, with a short, focused note on protecting paths, recovering trashed files, exit codes, `--dry-run`, and the networked-filesystem concurrency knob, pointing to `topo --help` for the rest.

### 4. A harder, more honest test suite
- The privileged-delete path is now checked by running the exact `rm` argv it builds against real fixtures (a symlink is unlinked without following it; a subtree is removed without touching a sibling), rather than only asserting the command string.
- Permission handling is exercised against real `chmod 0o000` directories, not an injected `OSError`; the cargo-built engine test skips cleanly on a machine with no Rust toolchain instead of erroring; a pseudo-terminal integration suite drives the real menu and asserts a genuine SIGINT/SIGTERM resets the terminal and exits 130/143; and the test environment now isolates the XDG base directories and `PATH`, not just `HOME`.

---

## Verification
- The Python suite contains 1,206 tests and runs on Python 3.10 and 3.14 in CI.
- CI enforces Ruff linting and formatting, Mypy including untyped function bodies, Tach module boundaries, Vulture dead-code checks, ShellCheck, Cargo Clippy/formatting, and 22 Rust unit and integration tests.
- Both bundled musl engines are checked against `topo-core/engine.stamp` and against a fresh build of the current Rust source, so a committed binary cannot drift from the source it claims to come from.
- Release jobs build x86_64 and aarch64 static musl engines plus DEB and RPM packages, then smoke-test script installation, package installation/removal, multiple Linux distributions, and ARM64 execution under QEMU.
- Every published installer, source archive, engine, and package is covered by `SHA256SUMS`; the manifest is signed with the project release key before the GitHub Release is created.

# Topo v1.2.0 中文发布说明

Topo v1.2.0 是一次以健壮性与正确性加固为主的版本，重点在交互式终端 UI、打包与更新的可靠性、文档的准确性，以及测试套件的保真度。它落实了自 v1.1.9 以来完成的两轮端到端审查——文档 ↔ 实现 ↔ 发布一致性，以及 TUI / 终端状态恢复——此外还有一轮测试覆盖可信度审查。正确运行所依赖的行为没有任何改变；改变的是 TUI 边角情形下会发生什么、用包安装的 topo 如何更新，以及 README 与构建产物对自身的描述。

---

## 主要更新

### 1. 更健壮的交互式 UI
- Analyze 浏览器在空目录里按 Space 不再崩溃：此前在无可选项的视图上按它会抛 `IndexError` 并打印回溯；现在空列表上该键被忽略，与其它所有选择器一致。
- 卸载的最终确认屏现在会净化它绘制的应用名与每一条残留路径。这是全套里仅有的两个把可被攻击者影响的文本（`.desktop` 的 `Name=` 字段、磁盘上的目录名）原样送进终端的渲染点，构造过的名字可在"你确认删除"的那一屏注入光标/颜色控制符或拆断一行。
- 扫描途中按 Ctrl-C 不再在 scrollback 里留下一行残标题：spinner 现在会在终端复位**之前**被停下，睡在间隔里的一帧无法再重绘到刚恢复的屏幕上。
- 离开报告（Ctrl-C，或报告后提示处按 ESC）回到 shell 时不再闪一下空白备用屏——菜单只在确实要重绘时才重新进入备用屏。

### 2. 可靠的打包与更新
- DEB 与 RPM 包现在依赖 `gpg`——`topo update` 需要它来校验已签名的发行版，缺少它便拒绝执行。此前在最小化安装的主机上用包装的 topo 无法更新，而没有任何东西把 `gpg` 拉进来。
- 用 `--version X` 构建包时，现在也会把该版本写进运行时的 `VERSION` 文件，于是 `topo --version` 与 dpkg/rpm 报告的版本一致，而不再显示检出时的旧版本。

### 3. 与程序相符的文档
- `topo history` 的 README 示例现在展示**真实**的每会话两行输出（`started -> ended command` 头行，以及 `removed / trashed / skipped / failed` 计数），取自实际渲染器，而非一个命令从未打印过的单行形式。
- 运行要求现在列出 openSUSE / Zypper——一个此前被安装说明遗漏的一等支持平台——以及 `gpg`，并附一段简短聚焦的说明：保护路径、恢复回收站文件、退出码、`--dry-run` 与网络文件系统的并发旋钮，其余指向 `topo --help`。

### 4. 更硬、更诚实的测试套件
- 特权删除路径现在通过对真实 fixture 执行它构造的那条 `rm` argv 来验证（符号链接被 unlink 而不跟进；子树被删而不动同级），而不再只断言命令字符串。
- 权限处理针对真实的 `chmod 0o000` 目录验证，而非注入的 `OSError`；依赖 cargo 构建引擎的测试在没有 Rust 工具链的机器上干净跳过而非报错；一个伪终端集成套件驱动真实菜单，断言真的 SIGINT/SIGTERM 会复位终端并以 130/143 退出；测试环境现在隔离 XDG 基目录与 `PATH`，而不只是 `HOME`。

---

## 验证
- Python 测试套件包含 1,206 项测试，并在 CI 中覆盖 Python 3.10 与 3.14。
- CI 持续检查 Ruff lint/format、包含未注解函数体的 Mypy、Tach 模块边界、Vulture 死代码、ShellCheck、Cargo Clippy/format 以及 22 项 Rust 单元与集成测试。
- 两个内置 musl engine 都会与 `topo-core/engine.stamp` 以及当前 Rust 源码的全新构建对照，使已提交的二进制无法与它声称来源的源码发生漂移。
- Release 工作流构建 x86_64 与 aarch64 静态 musl engine、DEB 和 RPM，并验证脚本安装、系统包安装与移除、多种 Linux 发行版及 QEMU 下的 ARM64 执行。
- 发布的 installer、源码归档、engine 与系统包全部纳入 `SHA256SUMS`；GitHub Release 创建前会使用项目发布密钥对清单签名。
