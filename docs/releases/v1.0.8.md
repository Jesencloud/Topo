# Topo v1.0.8

Topo v1.0.8 is a polish release that eliminates terminal screen flickering during main menu transitions and prevents redundant disk re-scans when navigating in and out of the Analyze module.

---

## Highlights

### 1. Seamless Menu Transitions & Zero Screen Flickering (`src/main.py`)
- **Root Cause**: Previously, the main menu exited the Alternate Screen Buffer (`restore_terminal()`) between every action. When dispatching to submodules (e.g. `clean`, `uninstall`, `optimize`, `analyze`, `status`), the shell prompt would flash onto the primary screen for several frames before the submodule opened its own screen buffer.
- **Fix**: The main menu loop now remains inside a single, continuous Alternate Screen Buffer lifecycle across actions. Submodule transitions are smooth, instant, and completely flicker-free.

### 2. Elimination of Redundant Home Re-scans in Disk Analysis (`src/core/analyze.py`)
- **Root Cause**: When opening `Analyze`, scanning large secondary paths (such as `/usr`) generated hundreds of directory cache entries, which exceeded the LRU entry limit and evicted the freshly-scanned Home root (`~`) from `ScanCache`. As a result, exiting to the main menu and re-entering `Analyze` triggered a full, unnecessary re-scan of the entire Home directory.
- **Fix**:
  - `run_deep_analysis()` now re-pins the root Home scan result in `ScanCache` immediately after parallel secondary scans complete, keeping it hot in memory.
  - `_parallel_scan_sizes()` now triggers the `"Analyzing Linux insights, please wait..."` progress spinner only when actual disk I/O is required (via the new `on_scan_start` callback), ensuring zero UI stutter on cache hits.

# Topo v1.0.8 中文发布说明

Topo v1.0.8 为交互体验与性能细节优化版本，彻底解决了主菜单切换功能时的终端闪屏问题，并消除了反复进出磁盘分析（Analyze）模块时的冗余全盘重扫开销。

---

## 核心亮点

### 1. 消除菜单功能切换时的终端闪屏（`src/main.py`）
- **问题根源**：主菜单此前在每次用户选择功能后都会主动退出备用屏幕缓冲区（Alternate Screen Buffer），导致终端 Shell 提示符在功能跳转的毫秒级间隙中短暂闪烁在主屏幕上。
- **优化修复**：将备用屏幕生命周期贯穿于主菜单调度循环中。在主菜单与各子模块（清理、卸载、维护、分析、系统状态）之间切换时无缝衔接，带来零闪烁、极致顺滑的控制台体验。

### 2. 避免反复进入 Analyze 模块时的 Home 目录冗余重扫（`src/core/analyze.py`）
- **问题根源**：首次进入 Analyze 扫描 Home 目录后，后台并发扫描大容量次级目录（如 `/usr`）产生的大量缓存节点触碰了 LRU 上限，导致刚刚扫描好的 Home 根节点被挤出 `ScanCache`。当用户退回主菜单再次进入 Analyze 时，会触发不必要的全盘重新扫描。
- **优化修复**：
  - 在次级并发扫描完成后，对有效的 Home 根节点结果进行**防抖热点重置（Re-pinning）**，确保在同一生命周期内二次进入 Analyze 实现秒级即时呈现。
  - `_parallel_scan_sizes()` 引入 `on_scan_start` 回调机制：仅在真正需要执行 Rust 磁盘 I/O 时才打印等待提示，在缓存完全命中时实现零卡顿瞬时进入。
