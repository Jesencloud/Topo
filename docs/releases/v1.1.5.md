# Topo v1.1.5

Topo v1.1.5 is a correctness and resilience release focused on the paths where a cleanup tool must be most conservative: preserving user protections, keeping package and swap state recoverable, reporting reclaimed space accurately, and remaining usable when Linux exposes data that is not valid UTF-8.

---

## Highlights

### 1. Safer Whitelist and Configuration Storage
- Added a single atomic JSON storage layer for the whitelist, configuration, and detected-application registry. Updates are written to a sibling temporary file, synchronized, and then atomically replaced instead of truncating the live file first.
- A corrupt or unreadable whitelist is no longer treated as an empty whitelist. Topo warns the user and freezes whitelist writes so existing protections remain recoverable instead of being silently discarded.
- Whitelist commands now distinguish an unchanged entry from a failed write, preventing storage failures from being reported as successful no-ops.
- Invalid derived application data is rebuilt safely, while an unreadable configuration falls back to conservative defaults.

### 2. Reliable Behavior with Non-UTF-8 System Data
- Subprocess output is decoded defensively, so a filename, package description, temporary path, or GPG identity containing non-UTF-8 bytes can no longer terminate a Topo command with a traceback.
- Update checks, downloads, and signature verification retain their existing fail-closed behavior when malformed text is encountered.
- Shell startup files are handled without re-encoding their contents. `topo link` and `topo remove` now preserve arbitrary bytes, file modes, ownership where possible, and symlink targets while editing the managed PATH entry.
- Text reads across procfs, sysfs, `/etc/os-release`, installation metadata, and `VERSION` now use an explicit decoding policy, preventing one unusual system value from breaking an otherwise unrelated command.

### 3. Accurate Cleanup and Reclaimed-Space Reporting
- DNF cleanup now removes the package and solv caches that the preview actually measures, while preserving repository metadata that would require another download.
- Topo also cleans stale repository directories and package caches maintained by `dnf5daemon-server` and PackageKit, but stands down during active RPM transactions or staged offline updates.
- Journal cleanup now reads `journalctl` from the stream it actually reports on and sums the per-directory `Vacuuming done` totals, so the displayed reclaimed space matches systemd's result.
- Size parsing no longer mistakes package counts, path fragments, negative values, or malformed thousands separators for reclaimed bytes. Pacman removal totals are anchored to its explicit summary line.

### 4. Safer Optimize Operations
- Optimize can flush both systemd-resolved and nscd DNS caches when their daemons are active, helping changed DNS records take effect without unnecessary privilege prompts.
- Swap restoration now runs even if `swapoff -a` times out. Topo verifies the resulting state through `/proc/swaps` and prints an explicit failure warning if swap was not restored.
- The swap timeout scales with the amount of active swap instead of relying on a fixed deadline that may be too short for slower storage.

### 5. Package Transaction and Quality-Gate Hardening
- Destructive package transactions no longer inherit a fixed five-minute timeout. Kernel removals, application uninstalls, and Topo package upgrades are allowed to finish instead of risking a SIGKILL halfway through a dpkg or RPM transaction.
- Captured package-manager operations remain non-interactive, while terminal-attached Topo package removal and upgrade commands remain cancellable by the user.
- Added structural regression guards for atomic JSON ownership, subprocess decoding, text-file decoding, and package-transaction timeout policy, alongside focused tests for every corrected failure path.
- The main CI workflow can now be started manually for any branch from GitHub Actions without creating an empty commit.

---

## Verification
- The full local gate covers Ruff formatting and linting, Mypy, Tach, Vulture, ShellCheck, Clippy, pytest, Cargo tests, and bundled-engine consistency.
- Regression tests exercise corrupt and non-UTF-8 state files, real non-UTF-8 child-process output, interrupted swap reset, journalctl transcripts, DNF cache ownership, active package transactions, offline updates, shell-file symlinks, and slow package operations.
- Structural tests scan the source tree so future subprocess, JSON, text-decoding, and destructive package-transaction call sites cannot silently reintroduce the corrected defect classes.

# Topo v1.1.5 中文发布说明

Topo v1.1.5 是一次以正确性和故障恢复能力为重点的版本更新，集中加固清理工具最需要保守处理的路径：保留用户保护规则、避免包管理器与 swap 状态受损、准确报告释放空间，并确保 Linux 系统中出现非 UTF-8 数据时命令仍可正常运行。

---

## 主要更新

### 1. 更安全的白名单与配置存储
- 为白名单、配置和已检测应用注册表建立统一的原子 JSON 存储层：先写入同目录临时文件并同步，再原子替换正式文件，不再直接截断原文件后写入。
- 损坏或不可读的白名单不再被当作空白名单。Topo 会提示用户并暂停白名单写入，使已有保护内容保持可恢复，而不是被静默清空。
- 白名单命令现在能区分“内容未变化”和“写入失败”，避免把磁盘写入错误误报为成功。
- 派生的应用检测数据损坏时会安全重建；配置不可读时则回退到更保守的默认设置。

### 2. 完善非 UTF-8 系统数据兼容性
- 子进程输出采用容错解码，文件名、软件包描述、临时目录或 GPG 身份中存在非 UTF-8 字节时，不再导致 Topo 以 traceback 崩溃。
- 更新检查、下载和签名验证在遇到异常文本时仍保持原有的保守拒绝策略，不会放宽安全校验。
- Shell 启动文件不再经过解码后重新编码。`topo link` 与 `topo remove` 编辑 PATH 标记时，会保留原始字节、文件权限、可恢复的所有权以及符号链接目标。
- procfs、sysfs、`/etc/os-release`、安装来源、锁文件和 `VERSION` 等文本读取统一采用明确的解码策略，单个异常系统值不再拖垮整个命令。

### 3. 更准确的清理行为与空间统计
- DNF 清理现在会删除预览实际统计的 packages 与 solv 缓存，同时保留需要重新联网下载的仓库元数据。
- Topo 还会清理由已删除仓库遗留的目录，以及 `dnf5daemon-server` 和 PackageKit 维护的缓存；RPM 事务正在运行或离线更新已就绪时会主动跳过。
- Journal 清理改为读取 `journalctl` 实际输出所在的流，并汇总多个日志目录各自报告的 `Vacuuming done` 数值，使释放空间与 systemd 的结果一致。
- 尺寸解析不再把软件包数量、路径片段、负数或错误的千分位格式识别为释放空间；Pacman 的卸载空间只读取明确的汇总行。

### 4. 更安全的 Optimize 操作
- 检测到对应服务运行时，Optimize 可以刷新 systemd-resolved 与 nscd 的 DNS 缓存，让已经变更的 DNS 记录及时生效，并避免不必要的提权请求。
- 即使 `swapoff -a` 超时，Topo 也会继续执行 swap 恢复，并通过 `/proc/swaps` 校验最终状态；恢复失败时会显示明确的错误提示。
- swap 操作超时会根据当前 swap 容量动态计算，不再用固定时限假设所有存储设备速度相同。

### 5. 包事务与工程门禁加固
- 破坏性包事务不再继承固定的五分钟超时。内核清理、应用卸载和 Topo 软件包升级会等待包管理器完成，避免在 dpkg 或 RPM 事务中途发送 SIGKILL。
- 后台捕获输出的包管理器操作继续保持非交互模式；直接连接终端的 Topo 软件包卸载与升级仍可由用户主动中断。
- 新增结构性回归检查，覆盖原子 JSON 存储、子进程解码、文本文件解码和包事务超时策略，并为本轮修复的异常路径补充针对性测试。
- 主 CI 工作流现在支持从 GitHub Actions 页面针对任意分支手动运行，无需创建空提交。

- 回归测试覆盖损坏及非 UTF-8 状态文件、真实非 UTF-8 子进程输出、swap 重置中断、journalctl 实际输出、DNF 缓存边界、活动包事务、离线更新、Shell 文件符号链接和慢速包操作。
- 结构性测试扫描整个源码树，确保今后新增的子进程、JSON、文本解码和破坏性包事务调用点不会静默重新引入本轮修复的问题类型。
