# Topo v1.1.3

Topo v1.1.3 is a correctness release aimed at the distributions Topo claimed to support but did not always speak to. One package-manager matrix replaces five drifted copies of "what distro is this", every command whose output gets parsed now runs in the C locale, and the cleanup, uninstall and optimize paths that silently did nothing on Debian, Ubuntu, openSUSE or dnf5 now do what they promise. Alongside that, every command returns a meaningful exit code, the Rust scanner stops dropping directories that merely share a name with `/proc` or `/dev`, and the release pipeline's own assertions were repaired.

---

## Highlights

### 1. One Distro Matrix, and Output Parsed in the C Locale
- `src/core/package_manager.py` now holds a single row per package manager — ids, `ID_LIKE` family, query tool, admin tools, cache-clean arguments, release asset format, and Topo's own upgrade/remove argv. The five hand-written copies it replaces had already drifted into disagreeing about the same machine: on Arch, `topo clean` and `topo uninstall` worked while `topo update` and `topo remove` answered "Unsupported Linux distribution"; openSUSE's package cache was never cleaned; and `doctor` probed `apt` and `dnf` rather than the `apt-get`, `dpkg-query` and `dnf5` that Topo actually runs.
- Two lookups, because there are genuinely two questions: which manager owns this machine (id, then `ID_LIKE` family, then PATH), and which release asset may be handed to it (exact ids only, so a box with `dpkg` installed for `alien` is never offered a `.deb`).
- Every output parser matched English words ("disabled", "ii", "Installed Size") and English unit suffixes, so a zh_CN, de_DE or fr_FR desktop parsed nothing at all. `run_command` gained an environment overlay, layered onto `os.environ` rather than replacing it, and each command whose stdout is read — `snap list`, `dpkg-query`, apt/dnf transactions, `journalctl`, `pacman -Qi`, `flatpak list`, `ps -eo`, `rpm -qf` — now asks for the C locale. On a zh_CN box, `rpm -qf`'s translated "not owned by any package" sentence was being stored as a package name.
- Debian keeps `/sbin` and `/usr/sbin` out of a non-root PATH and still ships them unmerged, so `shutil.which()` reported `fstrim`, `ldconfig`, `locale-gen`, `swapoff`/`swapon` and `updatedb` as absent and Optimize silently skipped all five. A dedicated admin-tool lookup finds them.
- openSUSE and SLES are rpm distros without dnf, so labelling their packages "DNF" sent uninstall into a command that is not installed. Removal there is `zypper --non-interactive remove --clean-deps`, the family is read from os-release rather than from PATH, and the branch that used to guess `dnf remove` for anything unrecognised is now an explicit failure.

### 2. Cleanup That Reports Its Real Numbers
- Kernel cleaning worked on neither family. On Debian it kept the running kernel and the `linux-image-amd64` metapackage — which won the "one previous version" slot because `dpkg -l` sorts alphabetically — and purged every real fallback; on Ubuntu the metapackage test compared a one-element slice against a digit, so every kernel was written off as a metapackage. A kernel is now a name that carries a version (`^linux-image-\d`), the running kernel is matched on every number in its name rather than a prefix, and candidates are sorted by that key instead of alphabetically, which had put `-100-generic` ahead of `-91-generic` and kept the oldest kernel while purging the newest.
- On Fedora 41+ the dnf half asked `repoquery --installonly --installed`, a pair dnf5 refuses outright, so the cleaner returned empty-handed without printing a line. Selection is now librpm's own `--latest-limit=-2`, and the five or six packages that make up one kernel are grouped by version into a single transaction — the old code counted rows, removed four of five, and called the leftover `kernel-modules` a fallback kernel.
- Kernels are cleaned before the orphan sweep now, since purging `linux-image-X` orphans its `linux-modules-X`; in the old order those hundreds of megabytes waited for the next `topo clean`.
- Freed bytes and item counts come from apt's and dnf's own transaction summaries — in dnf4's wording as well as dnf5's — instead of a regex over the whole transcript. Measured against a real `dnf remove` of two packages totalling 576 KiB, the old expressions answered 19278 bytes (the leading digits of a repository hash in the table's first row) and 5 packages. A summary neither pattern can read now prints nothing at all rather than a guess.
- `apt-get clean` also unlinks `/var/cache/apt/pkgcache.bin` and `srcpkgcache.bin` — 44.5 MB each on `debian:stable-slim`, and unmentioned in `apt-get(8)` — which no report accounted for. All three paths are measured now: 93.1 MiB where the old row printed the 8.2 MiB in `archives/` alone.
- On a dnf5 box `/var/cache/dnf5daemon-server` (1.1 GB here) sat beside `/var/cache/libdnf5` (102 MB) and only the smaller one was counted; every existing directory of the family is measured now, and apt's `partial/` is no longer counted twice. `/var/cache/apt/archives/partial` is never deleted, because apt fails outright once it is gone and never recreates it; its contents stay cleanable.
- Stale-temp cleanup no longer treats the session ssh-agent as abandoned junk: Debian and Ubuntu ship `use-ssh-agent`, so the socket lives at `/tmp/ssh-XXXXXXXX/agent.PID`, and a socket's timestamps never move once it is bound. Sockets, FIFOs and device nodes are out of scope now, and so is a directory holding one. Editor backups and swap files moved to their own, wider age window, so an open `vim` session can never fall inside it.
- `pgrep -x`/`pkill -x` match the kernel's `comm` field, and procps-ng refuses a pattern longer than that field instead of matching the truncated name, so every name over 15 characters ("google-chrome-stable") reported "not running" for a running process and no signal ever reached it.

### 3. Uninstall Previews What Really Leaves
- Ticking one small entry can take half a desktop with it — `apt-get purge`, `dnf remove`, `pacman -Rns` and `zypper remove` all pull out whatever depends on the package — and the confirmation screen listed only the entry itself. The preview now draws a yellow "also removes N: a, b, c, d +K more" line under the row, asked once per selected app with the queries overlapping in a thread pool. Every query is read-only and unprivileged so the password prompt still comes *after* the preview: apt uses `purge -s`, pacman `--print-format %n`, and the rpm family is asked what requires the package. The list is a floor rather than a promise, and an unparsable reply leaves the preview exactly as it was.
- The APT flow ended in a system-wide `sudo apt-get autoremove --purge -y` with its output discarded: it took auto-installed packages that predated Topo and appeared in no preview, while the per-app branch beside it cleaned no orphans at all. The preview query and the removal now differ by `-s` versus `-y` and nothing else, with `--autoremove` on both sides, and a new test pins that invariant — any flag added to one side reopens the gap.
- `dpkg-query -W` now asks for the status pair, `${Essential}` and `${Priority}` alongside the size. A package removed without `--purge` stays in the database at "rc" with its old Installed-Size, so the list was offering space that had been freed long ago. Essential and required/important packages are excluded by dpkg's own answer instead of by name lists written for Fedora, and a new "fonts" segment protects the 100 MB+ CJK bundles that the "anything this big is a user app" fallback used to offer up — removing one turns every Chinese, Japanese and Korean glyph on the desktop into a box.
- `Multi-Arch: same` packages keep their `:arch` qualifier in `/var/lib/dpkg/info`, more than half the entries on a stock `ubuntu:24.04`, so "most recently installed first" collapsed for all of them; and `dpkg-query -S` puts every owner of a path on one comma-separated line, where splitting on the first colon cut `libc6:amd64` in half and turned the rest into a package name that does not exist.
- The scan and the removal stopped paying per app: the residue index `run_full_scan` already built is reused (so the preview can no longer disagree with the row that was picked), `/proc` is read once instead of forking a `pgrep -x` per candidate name per app, and the SIGTERM grace period is waited through once for the whole selection rather than once per app — ten running apps used to spend fifteen seconds there. The password is asked for only when something in the selection really goes through a system package manager.
- Having a package tool is not having its packages: installing `alien` puts `dpkg-query` on Fedora and `rpm` on Debian. Both full scanners now ask the database before forking a tool with a 60-second timeout, and the rpm guard asks whether `/var/lib/rpm` holds any non-empty file rather than naming a backend's file, so an unfamiliar backend still counts as a database.
- Candidate process names go through the real name matcher instead of a two-character substring test, where an app id of "go" matched a running Brave profile and would have been handed to `pkill -9`.

### 4. Scanner and Analyze Accuracy
- The Rust engine matched its skip list against a directory's name at any depth, so a developer's `~/dev`, a `~/media` or a `node_modules/dev` was dropped from the walk entirely — not counted in the total, not listed in Analyze, with nothing on screen to say a directory had been left out. On a 10 MB fixture the engine reported 1 MB where `du` reported 10 MB, and the same walker backs `--single`, so the uninstall and clean screens were short by the same amount. The six names now also have to be actual mount points (a different `st_dev` than their parent), which `/proc`, `/sys`, `/dev`, `/run` and a bind-mounted `~/chroot/proc` still are. The device is read lazily, so a directory holding none of those names pays nothing.
- Root-view percentages measure each row against the filesystem it lives on and clamp at 100%; a separate `/home` no longer printed 2500% over a small `/`.
- Analyze stopped spending engine forks: old-item rows are sized from the parent's single scan instead of one fork each (which also evicted the Home tree from the cache), sub-view rows are ranked before they are built so only the 50 that survive the cut pay for cache/age metadata, and one `scandir` sweep now decides preview versus full scan.
- Snap is shown under `/var/lib/snapd`, snap-packaged Docker data is found through a new fallback-path field, and a missing `xdg-open` is reported instead of doing nothing — with its stdin detached so a terminal handler cannot steal the keys the screen is waiting for.
- `src/core/bin/topo-core-{x86_64,aarch64}` were rebuilt from this source as musl statics, so a git or `--minimal` install gets the fix rather than the old numbers.

### 5. A Status Report Worth Trusting
- A kernel without `/proc/loadavg` turned the whole screen into a traceback and killed the TUI session, because nothing above `show_status` catches `OSError`. Load answers "N/A" now, and unmeasurable filesystems are dropped for the same reason.
- A battery that is present but unreadable returns nothing instead of `(0, "N/A", "")`, which rendered as a red 0% bar — indistinguishable from a pack about to die. Batteries are found by globbing `BAT*` rather than assuming `BAT0`, and health reads either unit family (`energy_*` µWh or `charge_*` µAh); only one exists per machine, so charge-based packs previously showed no health at all.
- One row per filesystem behind `/`, `~` and `/var`, instead of a single row measuring `$HOME`'s: Debian's guided partitioning offers separate `/home` and `/var`, and a full `/var` breaks apt long before `$HOME` notices. The verdict now tracks the fullest filesystem, and rows are deduplicated by the measured `(used, total)` pair rather than by `st_dev`, since btrfs gives every subvolume its own device id.
- The verdict held its own copies of the temperature limits and derived severity by keyword-matching its own prose, so a full disk was reported as "heavy load"; k10temp `Tdie` now outranks `Tctl`, so the parts that carry a +27 °C control offset stop reporting the offset value; and the label column is sized from a table of every label the report prints, so "Overall Status:" no longer pushes its value a column right.
- The probes got cheaper and less able to block: one `/sys/class/hwmon` walk shared by the temperature and fan probes, `temp*_label` read before the ~20× more expensive `temp*_input` (13.35 ms → 2.08 ms with the same sensor selected), the `/sys/class/drm` body no longer run once per display connector, `nvidia-smi` cut from a 10-second timeout to 3, and each probe run immediately before the row that needs it.
- `get_cpu_load_summary` and `get_battery_info` hand back numbers instead of having the verdict parse their display strings, which also fixes battery details rendering as "| Cycles: 244" when health is unreadable.
- The CPU, fan, memory, disk and battery rows carry clearer glyphs, and the battery icon switches at the same 20% boundary its colour uses.

### 6. A Reworked Optimize Task Set
- Dropped `run_sysctl_optimize` (wrote kernel tunables no cleanup needs) and `run_tracker_miner_reset` (discards a search index rather than optimizing it); added GLib schema compilation, icon cache refresh, locate database refresh, and `systemd reset-failed` for both the user and system scopes, with only the reset half asking for privileges. `updatedb` defers to an enabled plocate/mlocate timer *or* `cron.daily` entry, so it never duplicates a job the distro already schedules.
- zram-backed swap is never reset: `swapon -a` only restores fstab entries, so `swapoff -a` would strand a zram box until reboot. An unreadable `/proc/swaps` counts as unsafe.
- `fc-cache` runs the user pass first and the privileged one only when sudo is available, so a machine without sudo still gets its own cache.
- `apt-get update` joined the repository-refresh table ahead of `pkcon`; without it the task was a no-op across the whole Debian family.
- Browser VACUUM patterns are expanded through `home.glob()`, which handles a wildcard at any depth — `Path(pattern).parent` could not, so every profile-level pattern matched nothing.

### 7. One Browser Path Table, and the Flatpak/Snap Layouts
- `core/browser_cache.py` became `core/browser_paths.py`: a browser's paths are a fact, and three policies that disagree read them — protection refuses to delete a profile, cleanup sweeps the caches beside it, optimization vacuums the databases inside it. Optimize carried its own copy of the snap and Flatpak roots, so a browser could be protected from cleanup and still unreachable for vacuuming. Each entry now declares its database engine and, where it differs, the glob from a profile root down to one profile; Flatpak and Snap relocations are derived from that instead of written out per browser per install format. Vacuum coverage goes from 6 browsers to 13, and a test fails if any other module grows a browser path literal again.
- Flatpak's unused runtimes pile up in `/var/lib/flatpak`, because Flathub's own instructions add the remote system-wide; both installations are swept now, and the system pass is skipped when there is none.
- A snap's cache is swept in `$SNAP_USER_DATA` as well as `$SNAP_USER_COMMON`, and snapd's and flatpak's exported `.desktop` entries now count as evidence that an app is installed — their stems never equal the cache folder name, so an installed app's cache looked orphaned.
- Steam's shader cache is found in the flatpak and snap installs, which are exactly the ones with tens of gigabytes to reclaim, with `~/.steam/steam` and its symlink target no longer swept twice.

### 8. Exit Codes, Configuration, and Safer Entry Points
- Every command exited 0 no matter what it printed, so a refused signature check, a package manager that returned non-zero, a cancelled removal and a doctor that found a dead engine were all indistinguishable from success: `topo update && deploy` deployed anyway. The contract is now 0 for "did what was asked" (including "nothing to do"), 1 for failure/refusal/cancellation, 2 for argparse, and 130 for an interrupt. The eleven sequential `if args.command == ...` comparisons became one dispatch table, which is what makes a single conversion point possible; a subparser added without a route now says so on stderr instead of printing the banner and exiting 0.
- `termios.error` is not an `OSError` subclass, so nothing caught it and a non-TTY stdin printed a raw traceback from the launcher. The interactive commands refuse a non-TTY in the router — above the lock, so a refusal never fights another instance for it — and point at `topo status` / `topo clean --dry-run` instead. `topo remove` now asks a real confirmation on the package path too; it used to go straight to `sudo apt remove -y topo` with no Topo-level question at all.
- `topo remove --yes` was added for the callers that legitimately have no terminal, checked before the isatty test so it also works behind a pipe. Without it the only alternative is `apt remove topo`, which skips the user-residue cleanup this command exists for.
- `update` and `remove` — the only commands that rewrite or delete the installation directory itself — joined the single-instance lock, so a concurrent `topo clean` can no longer be importing modules out of a tree being replaced.
- Three of the four keys in `config.json` had no consumer. `use_trash` now reaches the six deletions that are recoverable (caches and stale temp files still go permanently — trashing a cache frees nothing), `min_age_days` became a floor with one enforcement point that can only push a window further into the past, and `theme_color` is resolved after argparse so `--no-color` keeps winning. `config_version 2` marks a file whose values can be a deliberate choice, so upgrading never moves an existing install off the thresholds and title colour it has had. Both READMEs gained the Configuration section the keys never had.

### 9. Install, Update, and Packaging
- `install.sh` checked that `python3` existed, not what it was, so on Debian 11 (3.9) or RHEL 8 (3.6) it ticked every box, printed its success banner, and left behind a Topo that died on first run. The floor is 3.10, enforced in `install.sh`, in the launcher for the git and package paths that never run it, and by the deb's own `python3 (>= 3.10)` dependency. The rpm deliberately keeps a bare `python3`: openSUSE Leap 15.6's `python3` is 3.6 and the release workflow installs `python311` beside it where rpm's solver cannot see it, so a versioned `Requires` would make the rpm uninstallable on a distro it is built for.
- The engine architecture is a whitelist. It used to be derived by elimination — aarch64 for two spellings of it, x86_64 for everything else — so riscv64, armv7l and i686 got a binary the kernel refuses to exec, once per scan, instead of the pure-Python fallback the callers already have.
- The package asset name is a whitelist for the same reason: `.get(machine, "amd64")` meant an armv7l or riscv64 Debian asked for `topo_<v>-1_amd64.deb`, a file that exists — so the download succeeded and the checksum verified, and only `apt install` refused it, after the transfer.
- `topo remove` honours `TOPO_LINK_DIR`. Installing with `TOPO_LINK_DIR=/opt/bin` and then removing left a dangling symlink on PATH, so the next `topo` printed "No such file or directory" instead of a removed program. The sweep walks every launcher location `install.sh` supports and keeps both historical defaults, because a removal cannot assume the override in force now was in force at install time, or that the install was not done as root.
- `install.sh` resolves the launcher directory in shell rather than importing it from the installed tree. The script comes from `main` while the tree it unpacks is an arbitrary older release, so the import resolved against that release and any `install.sh --version v<older>` broke on a symbol it did not have.
- A package install writes no bytecode under `/usr`. `sudo topo clean` had CPython scatter `.pyc` files through `/usr/lib/topo/src/`, and dpkg and rpm delete only what they recorded and cannot remove a directory that still holds something, so `apt remove topo` left stale bytecode and the shell of empty directories around it. A script install keeps its cache and its startup time, since that tree is the user's own and goes away with it.
- The deb's filename carries its revision (`topo_1.1.3-1_amd64.deb`), which is the Version `dpkg-deb -f` reported all along; the old name claimed to be a native package with no revision at all.
- Prerelease tags get a source-only release. `--iteration 1` turns `v1.2.3-rc.1` into Version `1.2.3-rc.1-1`, which outranks the `1.2.3-1` that follows it, while Topo's own comparison orders the rc *below* the release — the two orderings disagree, so the rc-to-release `apt install` would be a refused downgrade. No package that could pin a machine to an rc is built at all; `install.sh` and `topo-src.tar.gz` still ship.
- One reader for `VERSION`. Three components each invented their own answer for "unreadable" (1.0.0, 0.0.0, "Unavailable"), so a missing file made `topo --version`, `topo doctor` and `topo update` disagree about what was installed — and the updater's 0.0.0 compared as older than every remote tag, which turned `topo update` into a silent, complete, unrequested reinstall. `~/.config/topo` and the state directory likewise have one source each, in place of six and three hand-written copies.
- `topo update` tells a missing `curl` apart from a failed release lookup, instead of blaming the release with `Invalid release tag: ''`. `doctor` reports version numbers rather than `curl --version`'s whole ~300-character link line, generates its package rows from the matrix (with an "Update Prerequisites" section that names the consequence of a missing `curl` or `gpg`), and marks the detected manager like every other row.

### 10. Quality Gates and CI
- `topo-core/engine.stamp` ties the committed engines to the sources beside them. `check.sh` step 4 used to build on the host and move the result over the tracked musl binary, leaving a glibc-dynamic engine that worked on that one box; it verifies now instead of overwriting. `packaging/build-engine.sh` is the only producer of `src/core/bin/` and the only owner of the static-ELF assertions, and both engine workflows call it rather than carrying their own `readelf` block.
- `topo-core/**` joined the engine workflow's path filters. A change to the Rust scanner used to run fmt, clippy and cargo test and then produce no binary — the workflow that cross-compiles both musl statics, packages the deb and rpm and smoke-installs them never triggered on the one kind of change that alters what those packages carry.
- Seventeen CI smoke assertions could not fail. bash exempts a negated command from errexit, so `! grep -F "sudo apt upgrade topo" <<<"$output"` printed the forbidden line and carried on; twelve were dead outright, and the five closing each smoke leg held only because they sat on the last line of their script, where appending anything below would have switched them off with no diff to show for it. Each is now a function whose failing branch is an explicit exit, and a new test sweeps every workflow for the shape.
- `requirements-dev.txt` pins all six dev tools, and `check.sh` step 1 asks CI's question (`ruff format --check`, `cargo fmt --check`) instead of rewriting the tree it was checking — a run that printed a green "Ruff format" had just made the change CI would have failed on.
- The suite grew from 788 to 861 tests, opening the cycle with a coverage push to 84% and closing it with shell-side tests that extract and run real blocks of `install.sh` and `check.sh` rather than grepping them for text.

## Verification
- The full local gate (Ruff, Ruff format, Mypy `--check-untyped-defs`, Tach, Vulture, ShellCheck, Clippy, pytest, cargo test) passes; 861 Python tests green.
- Cross-distro behaviour was verified against real systems rather than fixtures: Fedora 44 / dnf5 5.4.3.0 for the kernel and orphan work, `debian:stable-slim` with real `cowsay`/`tree` installs confirming that what left the machine equalled what the preview listed, `debian:11-slim` refusing the deb at `Depends: python3 (>= 3.10) but 3.9.2-3 is to be installed`, and `ubuntu:24.04` plus `debian:stable-slim` installing and running it.
- The bundled engines are byte-verified against `topo-core/engine.stamp`, and the scanner's mount-point rule was checked under `unshare -rm` with a tmpfs mounted on `dev/`, plus unit tests over all four device combinations.
- `dpkg-query` and dnf fixtures are byte-accurate transcriptions of the real tools (dpkg-query 1.23.7 over a synthetic `DPKG_ADMINDIR`), and every replaced expression was re-run against them to confirm the numbers it used to produce.
- The release workflow's three changed `run:` blocks were executed offline against fake files on both tag paths: a normal tag still produces 8 `SHA256SUMS` entries and 10 attached files, matching the live v1.1.2 release asset-for-asset; a prerelease produces 4 and 6, with no package among them.

# Topo v1.1.3 中文发布说明

Topo v1.1.3 是一次以正确性为主线的发布，针对的是那些 Topo 声称支持、却并没有真正「说对话」的发行版。一张统一的包管理器矩阵取代了五份各自漂移的「这是什么发行版」判断；所有需要解析输出的命令现在都在 C locale 下执行；在 Debian、Ubuntu、openSUSE 和 dnf5 上原本静默无所作为的清理、卸载与优化路径，现在会真正做它们承诺的事。此外，每个命令都会返回有意义的退出码，Rust 扫描器不再把只是「名字碰巧叫 `/proc`、`/dev`」的目录整个丢掉，发布流水线自身失效的断言也一并修好。

---

## 主要更新

### 1. 统一的发行版矩阵，以及 C locale 下的输出解析
- `src/core/package_manager.py` 现在为每个包管理器只保留一行事实：发行版 id、`ID_LIKE` 家族、查询工具、管理工具、清缓存参数、发布资产格式，以及 Topo 自身的升级/卸载 argv。它取代的五份手写副本早已漂移到对同一台机器给出不同答案：Arch 上 `topo clean`、`topo uninstall` 能用，而 `topo update`、`topo remove` 却回答「不支持的 Linux 发行版」；openSUSE 的包缓存从未被清理；`doctor` 探测的是 `apt` 和 `dnf`，而不是 Topo 实际调用的 `apt-get`、`dpkg-query` 与 `dnf5`。
- 保留两个查询入口，因为这确实是两个问题：哪个包管理器「拥有」这台机器（先 id，再 `ID_LIKE` 家族，最后 PATH）；以及可以给这台机器哪个发布资产（只认精确 id，所以为了 `alien` 而装了 `dpkg` 的机器绝不会被投喂 `.deb`）。
- 所有输出解析都在匹配英文单词（「disabled」「ii」「Installed Size」）和英文单位后缀，因此在 zh_CN、de_DE 或 fr_FR 桌面上什么都解析不到。`run_command` 新增环境变量叠加（叠在 `os.environ` 之上而非替换），凡是需要读取 stdout 的命令——`snap list`、`dpkg-query`、apt/dnf 事务、`journalctl`、`pacman -Qi`、`flatpak list`、`ps -eo`、`rpm -qf`——现在都要求 C locale。在 zh_CN 机器上，`rpm -qf` 那句被翻译过的「不属于任何软件包」曾被当成包名存了下来。
- Debian 不把 `/sbin`、`/usr/sbin` 放进非 root 的 PATH，而且这两个目录至今未合并，于是 `shutil.which()` 认为 `fstrim`、`ldconfig`、`locale-gen`、`swapoff`/`swapon`、`updatedb` 全都不存在，Optimize 静默跳过了这五项。现在由专门的管理工具查找逻辑负责找到它们。
- openSUSE 与 SLES 是没有 dnf 的 rpm 发行版，把它们的软件包标成「DNF」等于把卸载送进一个根本没安装的命令。这一族的卸载现在是 `zypper --non-interactive remove --clean-deps`，家族判断来自 os-release 而不是 PATH，而原先「认不出就猜 `dnf remove`」的兜底分支改为显式失败。

### 2. 报出真实数字的清理
- 内核清理在两大家族上都是失效的——在 Debian 上它保留了运行中的内核和 `linux-image-amd64` 元包（后者因为 `dpkg -l` 按字母排序而抢占了「上一个版本」的名额），把真正可回退的内核全部清掉；在 Ubuntu 上，元包判断拿一个单元素切片去和数字比较，于是每个内核都被当成元包放过。现在「内核」的定义是名字里带版本号（`^linux-image-\d`），运行中的内核按名字里的每个数字匹配而不是前缀匹配，候选项按同一套 key 排序而不是按字母序——后者曾把 `-100-generic` 排在 `-91-generic` 前面，结果保住最旧的、清掉最新的。
- 在 Fedora 41+ 上，dnf 分支查询 `repoquery --installonly --installed`，而 dnf5 明确拒绝这一对参数同时出现，于是清理器什么都没查到、也没打印任何一行。现在直接用 librpm 自己的 `--latest-limit=-2`，并把构成同一个内核的五六个软件包按版本归组进同一个事务——旧代码是按「行」计数，删掉五个中的四个，还把剩下那个 `kernel-modules` 当成回退内核。
- 内核清理现在排在孤立包清理之前：清掉 `linux-image-X` 会让它的 `linux-modules-X` 变成孤立包；按旧顺序，那几百 MB 要等到下一次 `topo clean` 才会被回收。
- 释放的空间与项目数现在取自 apt 和 dnf 自己的事务摘要（同时覆盖 dnf4 与 dnf5 两种措辞），不再用正则去扫整段输出。对着一次真实的 `dnf remove`（两个包，共 576 KiB）实测：旧表达式给出 19278 字节（其实是表格首行里仓库哈希的前几位数字）和 5 个包。两套模式都读不出摘要时，现在什么都不打印，而不是给一个猜测值。
- `apt-get clean` 还会删掉 `/var/cache/apt/pkgcache.bin` 与 `srcpkgcache.bin`——在 `debian:stable-slim` 上各 44.5 MB，且 `apt-get(8)` 手册对此毫无提及——这部分空间过去从未出现在任何报告里。现在三个路径一起计量：旧行只报 `archives/` 的 8.2 MiB，现在是 93.1 MiB。
- 在 dnf5 机器上，`/var/cache/dnf5daemon-server`（本机 1.1 GB）与 `/var/cache/libdnf5`（102 MB）并存，而过去只统计了较小的那个；现在同一家族下所有存在的目录都会被计量，apt 的 `partial/` 也不再被重复计算两次。`/var/cache/apt/archives/partial` 永不删除——一旦它消失，apt 会直接报错且不会自行重建；目录里的内容仍然可清。
- 临时文件清理不再把当前会话的 ssh-agent 当作垃圾：Debian 与 Ubuntu 启用了 `use-ssh-agent`，套接字位于 `/tmp/ssh-XXXXXXXX/agent.PID`，而套接字一旦绑定，其时间戳就永远不再变化。现在套接字、FIFO、设备节点都不在清理范围内，包含它们的目录也一样。编辑器备份与 swap 文件移到了自己更宽的时间窗口，因此一个正在编辑的 `vim` 会话绝不会落进清理范围。
- `pgrep -x`/`pkill -x` 匹配的是内核的 `comm` 字段，而 procps-ng 会直接拒绝超过该字段长度的模式，而不是去匹配被截断的名字，因此任何超过 15 个字符的名字（如「google-chrome-stable」）都会把运行中的进程报成「未运行」，也从未真正收到过信号。

### 3. 卸载预览现在会说出「还会带走什么」
- 勾选一个很小的条目，可能连半个桌面一起带走——`apt-get purge`、`dnf remove`、`pacman -Rns`、`zypper remove` 都会把依赖它的东西一并拖出——而确认界面过去只列出条目本身。现在预览会在该行下方画出一条黄色的「also removes N: a, b, c, d +K more」，对每个选中的应用各查一次，多个查询在线程池里重叠执行。所有查询都必须是只读且无需提权的，这样密码提示仍然排在预览**之后**：apt 用 `purge -s`，pacman 用 `--print-format %n`，rpm 一族则被问「谁依赖这个包」。这个清单是下界而非承诺，无法解析的回复会让预览保持原样。
- APT 流程最后会执行一次全系统的 `sudo apt-get autoremove --purge -y`，输出还被丢弃：它会带走早于 Topo 安装、且不在任何预览里的自动安装包；而旁边的单应用分支却完全不清理孤立包。现在预览查询与实际卸载之间只差 `-s` 与 `-y`，两侧都带 `--autoremove`，并有新测试钉住这个不变式——只给一侧加参数就会重新打开这个缺口。
- `dpkg-query -W` 现在连状态对、`${Essential}`、`${Priority}` 一起要。未加 `--purge` 卸载的包会以「rc」状态连同旧的 Installed-Size 留在数据库里，于是列表在提供早已释放掉的空间。Essential 与 required/important 包现在由 dpkg 自己的回答排除，而不是靠为 Fedora 写的名字清单；新增的「fonts」分段则保护那些 100 MB 以上的 CJK 字体包——过去「这么大一定是用户应用」的兜底会把它们列出来，而删掉一个就会让桌面上所有中日韩字形变成方框。
- `Multi-Arch: same` 的包在 `/var/lib/dpkg/info` 里保留 `:arch` 后缀（在原版 `ubuntu:24.04` 上超过一半条目如此），因此「最近安装优先」对它们全部失效；`dpkg-query -S` 会把一个路径的所有归属者放在同一行、以逗号分隔，而按第一个冒号切分会把 `libc6:amd64` 切成两半，并把后半段当成一个并不存在的包名。
- 扫描与卸载不再按应用重复付费：复用 `run_full_scan` 已经建好的残留索引（因此预览不可能与被勾选的那一行给出不同数字），`/proc` 只读一次而不是「每个应用的每个候选名字 fork 一次 `pgrep -x`」，SIGTERM 的宽限期对整批选择只等一次而不是每个应用等一次——十个运行中的应用过去要在这里花掉十五秒。只有当选中项里确实存在需要经过系统包管理器的项目时，才会请求密码。
- 「有工具」不等于「有那个数据库」：装了 `alien` 会让 Fedora 上出现 `dpkg-query`、Debian 上出现 `rpm`。两个完整扫描器现在都先问数据库，再决定是否 fork 一个带 60 秒超时的工具；rpm 侧的判断刻意换了形状——问 `/var/lib/rpm` 里是否存在任何非空文件，而不是指名某个后端的文件，这样一个没人见过的后端也仍然算作「有数据库」。
- 候选进程名现在走真正的名字匹配，而不是两字符子串判断——在这台机器上，应用 id「go」曾匹配到一个运行中的 Brave 配置目录，并会被交给 `pkill -9`。

### 4. 扫描器与 Analyze 的计量准确性
- Rust 引擎过去把跳过名单按「目录名」在任意深度上匹配，于是开发者的 `~/dev`、`~/media` 或某个 `node_modules/dev` 会被整个从遍历中丢掉——既不计入总量，也不出现在 Analyze 里，屏幕上更没有任何提示说有目录被略过。在一个 10 MB 的样本目录上，引擎报 1 MB 而 `du` 报 10 MB；`--single` 用的是同一个遍历器，所以卸载与清理界面上的体积也少了同样的量。现在这六个名字还必须真的是挂载点（`st_dev` 与父目录不同），而 `/proc`、`/sys`、`/dev`、`/run` 以及 bind 挂载的 `~/chroot/proc` 依然满足这一条。设备号是惰性读取的，因此不含这些名字的目录不付任何代价。
- 根视图的百分比现在按每一行所在的文件系统计算，并在 100% 处截断；独立的 `/home` 不会再在一个小 `/` 上打印出 2500%。
- Analyze 不再挥霍引擎调用：旧文件行的体积取自父目录那一次扫描，而不是每行 fork 一次（后者还会把 Home 的缓存树挤出去）；子视图的行先排名再构建，因此只有通过筛选的 50 行才需要付出缓存/时间元数据的代价；一次 `scandir` 扫描就能决定走预览还是完整扫描。
- snap 现在显示在 `/var/lib/snapd` 下，snap 打包的 Docker 数据通过新增的 fallback 路径字段找到；缺少 `xdg-open` 会被明确报出而不是什么都不做，并且它的 stdin 被分离，避免终端处理器抢走界面正在等待的按键。
- `src/core/bin/topo-core-{x86_64,aarch64}` 已按本次源码重新构建为 musl 静态二进制，因此 git 安装或 `--minimal` 安装拿到的是修好的版本，而不是旧数字。

### 5. 值得信任的 Status 报告
- 内核缺少 `/proc/loadavg` 时，整个界面会变成一段 traceback 并终止 TUI 会话——`show_status` 之上没有任何地方捕获 `OSError`。现在负载会回答「N/A」，无法计量的文件系统也基于同样理由被丢弃。
- 电池存在但读不出来时返回「无」，而不是过去的 `(0, "N/A", "")`——后者会渲染成一条红色的 0% 进度条，与一块即将耗尽的电池毫无区别。电池现在通过 `BAT*` 通配查找而不是假定 `BAT0`，健康度会读取两种单位家族（`energy_*` µWh 或 `charge_*` µAh）中存在的那一种；每台机器只有一种，因此基于电荷量的电池过去完全显示不出健康度。
- `/`、`~`、`/var` 背后的每个文件系统各占一行，而不是用一行去量 `$HOME` 所在的那个：Debian 的向导式分区会给出独立的 `/home` 与 `/var`，而 `/var` 满了会在 `$HOME` 还没察觉时就先把 apt 弄坏。总体结论现在跟随最满的那个文件系统；行去重依据是实测的 `(used, total)` 组合而不是 `st_dev`，因为 btrfs 会给每个子卷分配独立的设备号。
- 结论区过去自己另存了一份温度阈值，并靠对自己打印的文字做关键词匹配来判定严重程度，于是「磁盘满了」被报成了「负载偏高」；k10temp 的 `Tdie` 现在优先于 `Tctl`，那些带 +27 °C 控制偏移的型号不会再上报偏移后的数值；标签列宽按报告会打印的全部标签取表计算，「Overall Status:」不会再把它的值整体右推一格。
- 探测更便宜、也更不容易阻塞：温度与风扇共用一次 `/sys/class/hwmon` 遍历；先读 `temp*_label` 再读贵约 20 倍的 `temp*_input`（13.35 ms → 2.08 ms，选中的传感器不变）；`/sys/class/drm` 的探测体不再对每个显示接口各跑一遍；`nvidia-smi` 的超时从 10 秒降到 3 秒；每个探测都紧挨着需要它的那一行才执行。
- `get_cpu_load_summary` 与 `get_battery_info` 直接交出数字，而不是让结论区去解析它们的显示字符串；这同时修掉了健康度不可读时电池详情被渲染成「| Cycles: 244」的问题。
- CPU、风扇、内存、磁盘与电池行换上了更清晰的图标，电池图标的切换点与它的颜色共用同一个 20% 边界。

### 6. 重做后的 Optimize 任务集
- 移除 `run_sysctl_optimize`（写入的内核参数没有任何清理需要）与 `run_tracker_miner_reset`（那是丢弃搜索索引，而不是优化它）；新增 GLib schema 编译、图标缓存刷新、locate 数据库刷新，以及用户与系统两个作用域的 `systemd reset-failed`（只有 reset 那一半需要提权，列举从不提权）。`updatedb` 会让位给已启用的 plocate/mlocate timer **或** `cron.daily` 条目，因此绝不会重复发行版已经安排好的任务。
- 绝不重置 zram 交换空间：`swapon -a` 只恢复 fstab 中的条目，因此 `swapoff -a` 会让一台 zram 机器直到重启前都没有 swap。`/proc/swaps` 读不出来时按「不安全」处理。
- `fc-cache` 先跑用户级，只有在 sudo 可用时才跑特权级，因此没有 sudo 的机器至少仍能得到自己的字体缓存。
- `apt-get update` 加入了仓库刷新表，并排在 `pkcon` 之前；在此之前这个任务在整个 Debian 家族上都是空操作。
- 浏览器 VACUUM 的路径模式改用 `home.glob()` 展开，它能处理任意深度上的通配符——`Path(pattern).parent` 做不到，因此所有 profile 层级的模式过去都匹配不到任何东西。

### 7. 一张浏览器路径表，以及 Flatpak/Snap 布局
- `core/browser_cache.py` 变成 `core/browser_paths.py`：浏览器的路径是事实，而读取它的是三套彼此不同的策略——保护策略拒绝删除 profile，清理策略清扫它旁边的缓存，优化策略 VACUUM 它内部的数据库。Optimize 过去自带一份 snap 与 Flatpak 根目录副本，于是一个浏览器可能「受清理保护」却「优化触达不到」。现在每个条目声明自己的数据库引擎，以及（在不同的情况下）从 profile 根到单个 profile 的 glob；Flatpak 与 Snap 的重定位由此推导，而不是按「每个浏览器 × 每种安装格式」逐条写死。VACUUM 覆盖从 6 个浏览器提升到 13 个，并有一个测试在任何其他模块再次出现浏览器路径字面量时失败。
- Flatpak 未使用的 runtime 堆积在 `/var/lib/flatpak`，因为 Flathub 官方指引就是把远程仓库加在系统级；现在两种安装都会清扫，没有系统级安装时跳过该轮。
- snap 的缓存除 `$SNAP_USER_COMMON` 外也会清扫 `$SNAP_USER_DATA`；snapd 与 flatpak 导出的 `.desktop` 条目现在算作「应用已安装」的证据——它们的文件名从不等于缓存目录名，因此已安装应用的缓存过去看起来像孤立残留。
- Steam 的 shader 缓存现在能在 flatpak 与 snap 安装中找到，而那正是动辄能回收几十 GB 的两种安装方式；`~/.steam/steam` 与它的符号链接目标不再被重复清扫两次。

### 8. 退出码、配置项与更安全的入口
- 过去无论打印了什么，每个命令都退出 0：被拒的签名校验、返回非零的包管理器、被取消的卸载、以及发现引擎已损坏的 doctor，全都与成功无从区分——`topo update && deploy` 照样会部署。现在的契约是：0 表示「做了要求的事」（含「无事可做」），1 表示失败/拒绝/取消，2 表示 argparse 错误，130 表示中断。原先十一条顺序排列的 `if args.command == ...` 合并为一张分发表，这也正是「只有一个转换点」得以成立的前提；新增了子命令却忘了注册路由，现在会在 stderr 上说出来，而不是打印横幅然后退出 0。
- `termios.error` 并不是 `OSError` 的子类，因此一路向上没有任何地方捕获它，stdin 不是终端时启动器会打印一段裸 traceback。交互式命令现在在路由层拒绝非 TTY（位置在锁之上，因此一次拒绝绝不会去和另一个实例抢锁），并指向 `topo status` / `topo clean --dry-run`。`topo remove` 现在在包安装路径上也会真正询问一次确认——它过去直接执行 `sudo apt remove -y topo`，Topo 层面完全没有提问。
- 新增 `topo remove --yes`，供那些确实没有终端的合法调用者使用，检查位置在 isatty 判断之前，因此在管道背后同样有效。没有它的话，唯一替代就是 `apt remove topo`——而那会跳过这个命令存在的意义：用户侧残留清理。
- `update` 与 `remove`——唯一会重写或删除安装目录本身的两个命令——现在纳入单实例锁，因此并发的 `topo clean` 不可能再从一棵正在被替换的目录树里导入模块。
- `config.json` 四个键里有三个没有任何消费者。`use_trash` 现在覆盖六处「可恢复」的删除（缓存与临时文件仍然直接永久删除——把缓存丢进回收站等于没释放空间）；`min_age_days` 成为一个只有单一执行点的下限，它只能把时间窗口推得更早，绝不会拉近到现在；`theme_color` 在 argparse 之后解析，因此 `--no-color` 依然优先。`config_version 2` 用于标记「其中的值可能是刻意选择」的配置文件，因此升级绝不会把既有安装从它一直使用的阈值与标题颜色上挪开。两个 README 都补上了这些键从未有过的「配置」章节。

### 9. 安装、更新与打包
- `install.sh` 过去只检查 `python3` 是否存在，而不看它是什么版本，因此在 Debian 11（3.9）或 RHEL 8（3.6）上它每一项都打勾、打印成功横幅，留下一个首次运行就会死掉的 Topo。现在下限是 3.10，由 `install.sh`、由启动器（覆盖从不执行 `install.sh` 的 git 与包安装路径）、以及 deb 自身的 `python3 (>= 3.10)` 依赖三处共同保证。rpm 刻意保留裸 `python3`：openSUSE Leap 15.6 的 `python3` 是 3.6，而发布流水线会在其旁装上 `python311` 并做符号链接，rpm 的求解器看不到这一点——带版本的 `Requires` 会让这个 rpm 在它本该支持的发行版上无法安装。
- 引擎架构改为白名单。它过去靠排除法推导——两种拼法归为 aarch64，其余一律 x86_64——于是 riscv64、armv7l、i686 会拿到一个内核拒绝执行的二进制，每次扫描各拿一次，而不是退回调用方本来就有的纯 Python 实现。
- 发布资产名同理改为白名单：`.get(machine, "amd64")` 意味着 armv7l 或 riscv64 的 Debian 会去请求 `topo_<v>-1_amd64.deb`——那是一个真实存在的文件，于是下载成功、校验和通过，只有 `apt install` 在传输完成之后才拒绝它。
- `topo remove` 现在尊重 `TOPO_LINK_DIR`。用 `TOPO_LINK_DIR=/opt/bin` 安装再卸载，会在 PATH 上留下一个悬空符号链接，于是下一次 `topo` 打印的是「No such file or directory」而不是「命令已被移除」。清理现在会走遍 `install.sh` 支持的每一个启动器位置，并保留两个历史默认值——卸载不能假定「现在生效的覆盖值」就是「安装时生效的那个」，也不能假定当初不是以 root 安装的。
- `install.sh` 现在用 shell 自己解析启动器目录，而不是从已安装的目录树里导入：脚本来自 `main`，而它解开的目录树是某个任意的旧版本，导入会落到那个旧版本上——于是任何 `install.sh --version v<更旧>` 都会因为一个该版本没有的符号而失败。
- 包安装不再在 `/usr` 下写字节码。`sudo topo clean` 会让 CPython 把 `.pyc` 撒满 `/usr/lib/topo/src/`，而 dpkg 与 rpm 只删除自己记录过的文件、也无法删除仍有内容的目录，于是 `apt remove topo` 会留下过期字节码和一圈空目录。脚本安装保留自己的缓存与启动速度——那棵目录树属于用户，会随它一起消失。
- deb 的文件名现在带上修订号（`topo_1.1.3-1_amd64.deb`），这本就是 `dpkg-deb -f` 一直报告的 Version；旧名字则声称自己是一个没有修订号的原生包。
- 预发布 tag 只发布源码。`--iteration 1` 会把 `v1.2.3-rc.1` 变成 Version `1.2.3-rc.1-1`，它排在随后的 `1.2.3-1` 之上，而 Topo 自己的比较把 rc 排在正式版**之下**——两套排序互相矛盾，从 rc 升级到正式版的 `apt install` 会被当作降级而拒绝。现在干脆不构建任何可能把机器钉在 rc 上的包；`install.sh` 与 `topo-src.tar.gz` 照旧发布。
- `VERSION` 只有一个读取者。三个组件各自发明了「读不出来」的答案（1.0.0、0.0.0、「Unavailable」），因此文件缺失会让 `topo --version`、`topo doctor`、`topo update` 对「装的是什么版本」各说各话——而更新器的 0.0.0 比任何远端 tag 都旧，于是一个丢失的文件会把 `topo update` 变成一次静默、完整、且没人要求过的重装。`~/.config/topo` 与状态目录同样各自收敛为单一来源，取代了六处与三处手写副本。
- `topo update` 现在能区分「缺少 `curl`」与「查询发布失败」，不再用 `Invalid release tag: ''` 去责怪发布本身。`doctor` 报告版本号而不是 `curl --version` 那整行约 300 字符的链接库清单，包管理器相关的行由矩阵生成（并新增「Update Prerequisites」小节，把缺少 `curl` 或 `gpg` 的后果直接写出来），检测到的包管理器也像其他每一行一样带上状态标记。

### 10. 工程质量门禁与 CI
- `topo-core/engine.stamp` 把已提交的引擎与它旁边的源码绑在一起。`check.sh` 第 4 步过去会在本机构建、并把结果覆盖到那个纳入版本管理的 musl 二进制上，留下一个只在这台机器上能用的 glibc 动态链接引擎；现在它只验证、不覆盖。`packaging/build-engine.sh` 成为 `src/core/bin/` 的唯一生产者，也是静态 ELF 断言的唯一归属，两个引擎工作流都改为调用它，而不再各写一段 `readelf`。
- `topo-core/**` 加入了引擎工作流的路径过滤器。此前修改 Rust 扫描器只会触发 fmt、clippy 与 cargo test，却不产出任何二进制——那个负责交叉编译两个 musl 静态文件、打出 deb 与 rpm 并烟测安装的工作流，恰恰在「唯一会改变这些包内容」的改动上从不触发。
- 十七条 CI 烟测断言根本不可能失败。bash 让被取反的命令豁免于 errexit，因此 `! grep -F "sudo apt upgrade topo" <<<"$output"` 会把那行禁止出现的内容打印出来然后继续往下走；其中十二条彻底失效，另外五条仅因为恰好位于脚本最后一行而侥幸有效——在它们下面追加任何内容都会把断言悄悄关掉，且 diff 上看不出任何痕迹。现在每条都改为一个「失败分支是显式 exit」的函数，并有新测试扫描所有工作流检查这一形状。
- `requirements-dev.txt` 锁定全部六个开发工具版本；`check.sh` 第 1 步改为问 CI 的那个问题（`ruff format --check`、`cargo fmt --check`），而不是去改写它正在检查的代码树——一次打印出绿色「Ruff format」的运行，其实刚刚做完了 CI 本该判红的那个修改。
- 测试从 788 条增长到 861 条：这一周期以一次覆盖率推进（84%）开场，以「直接抽取并执行 `install.sh`、`check.sh` 里真实代码块」而非 grep 文本的 shell 侧测试收尾。
