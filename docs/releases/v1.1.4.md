# Topo v1.1.4

Topo v1.1.4 is about what Topo does when nobody is watching the screen. A redirected or piped run no longer drives a terminal it does not have, an interrupted run keeps the record of what it already deleted, and Analyze finally reports the result of a delete instead of leaving it to a sound. On top of that, the glyphs, counts, cancellation sentences and key hints that had grown up independently across the screens are now one vocabulary.

---

## Highlights

### 1. Correct Behavior Without a Terminal
- `setup_color_mode()` blanked the color constants on a non-TTY but left `CLEAR_SCREEN`, `CLEAR_LINE` and `ERASE_BELOW` intact, so a redirected run lost its colors and kept its cursor control. Measured on `topo optimize --dry-run > log`: 1510 bytes holding 27 escape sequences and 13 spinner frames, opening with `\033[2J`; now 805 bytes and zero escapes.
- The switch for terminal control is deliberately narrower than the one for color: `isatty()` alone, never `--no-color` or `NO_COLOR`. Those two ask Topo to stop coloring, not to stop repainting a frame in place.
- `terminal_state._write()` is the single funnel for every sequence that module emits, so guarding it also covers entering the alternate screen, hiding the cursor and mouse tracking. Ctrl-C on a redirected run used to append the whole reset — mouse-off ×4, cursor-on, graphics-reset, alt-screen-off — ahead of a `\033[2J`; that is now nothing at all.
- The progress spinner yields without starting its thread when there is no cursor to rewind, so a redirected run loses the animation and nothing else.
- The interactive guard used to ask only whether stdin was a keyboard, so `topo analyze | cat` sailed through it: the selector answered keys and the entire alternate-screen frame went down the pipe while the user drove a disk-deleting tool blind — and the run exited 0. Whether keys can be read and whether anyone can see what is drawn are separate questions, and both must now be answered yes.

### 2. Interrupts That Keep the Record
- Ctrl-C halfway through `clean` or `uninstall` used to throw away the report of the work already done: per-group output was still buffered inside `redirect_stdout`, the summary never ran, and no closing line reached the audit log. Every report step now runs from a `finally`, and each group flushes whatever it managed to print.
- Whether a run finished is decided by a flag set on the one path that completed every group, not by catching `KeyboardInterrupt`: SIGTERM arrives as `SystemExit` and a task can raise outright, and neither may sign off as `ended`.
- `record_history_session()` only whitelisted `started`/`ended`, so `interrupted` was silently dropped. The parser now closes a session on either terminal status and marks it `⚠ interrupted`; a session with no closing line still reads `incomplete`, which now means what it says.
- Uninstall reports per-app results from its own `finally`, under an `Uninstall interrupted` heading that adds `Anything not listed above was left untouched.`
- An interrupt no longer clears the screen. That erased exactly the record the interrupt made valuable — the `✓` lines of everything already deleted, along with the scrollback beneath them. The terminal has already been reset by the time this runs; what is worth erasing is a half-written spinner line, which is `CLEAR_LINE`'s job.

### 3. Analyze Reports What a Delete Did
- A successful delete used to say nothing at all except the delete sound, which is silent on a muted laptop or over ssh, and failures printed straight to the terminal where the full-frame repaint overwrote them within the same tick. The failed-scan branch had the same problem, papered over with a 1.5 s sleep.
- The removal helpers hand back `(removed, freed_bytes, problem)` and a batch returns a `DeleteOutcome` instead of printing, so the screen renders one notice line that arrives *with* the next frame.
- Notices are clamped to a single row, because the frame is positioned absolutely and a wrapped line pushes every row below it down until the next full repaint. Each notice carries its own glyph rather than a fixed yellow `⚠`, so a finished delete is no longer marked as a warning.

### 4. One Glyph Vocabulary
- Every site had invented its own: a finished step was `✓`, `✔`, `✅` or a hand-colored `✓`; a failure was `✗` or `❌` (28 times in `update.py` alone); a heading and a keypress prompt on the same screen both led with `➔`.
- There are six states worth distinguishing, and now six constants: `OK` (done), `FAIL` (attempted, did not work), `WARN` (needs attention, not a failure), `INFO` (an aside), `SKIP` (it exists, this run left it alone) and `NA` (not on this machine, so there was nothing to do). The last two are not interchangeable: `SKIP` where `NA` belongs claims a choice was made when there was nothing to choose.
- The emoji forms were the worst of it: `✅` / `❌` / `⚠️` are double-wide, so one of them in a column of narrow glyphs pushed every following field a cell to the right — which is why each emoji site carried a hand-tuned extra space, and why `doctor`'s rows drifted anyway. Every glyph is now single-column and carries its own color and reset, so the sentence after it stays uncolored.
- Three leading marks, not two: `➤` for a heading, `➔` for a line waiting on you, `●` for an aside. Folding headings into `➔` would make `topo clean`'s four group headers read as four questions. The in-list bullet `•` stays a fourth thing, and `☉` is gone.
- Two tests guard the one mistake this arrangement makes easy — a glyph added to the constants but forgotten in the color-name table keeps printing escapes under `--no-color`, silently, because every other glyph on the line obeys — and pin the single-column width the columns depend on.

### 5. Dry Runs That Look Like Dry Runs
- `clean --dry-run` reported a preview with the same green `✓` a real delete uses. The only difference between `✓ npm cache (9.3 KiB) would be cleaned` and `✓ Cleaned npm cache (9.3 KiB)` was a verb tense — the one difference a reader skimming a 40-line report does not catch, and the one that survives neither `--no-color` nor a paste with the escapes stripped.
- All 31 of `clean`'s report lines now use `SKIP` for a preview, the way `optimize` already did. Twenty-one sit inside `if dry_run:` and simply take the glyph; the other ten pick the glyph and the tense as one tuple, which is the actual fix — choosing them separately is why `✓ … would be cleaned` existed at all.
- The line is not dimmed as a whole, unlike `optimize`'s: there a skip is one row among completed ones, while in a dry run every row is a preview, so dimming all of them emphasizes nothing and dims the very text the reader came for.
- Two lines stay as they were: the summary was already tense-aware, and the zombie-process line keeps `detected`, because Topo signals the parents and `would be reaped` would promise what the real run does not deliver.
- The regression path is copying a line out of an existing cleaner, which is static, so the test is a source sweep: no line may carry `OK` and `would` together, and it asserts it matched more than twenty sites, because a sweep that found nothing would pass just as quietly.

### 6. Consistent Counts, Refusals and Selections
- One `plural()` helper replaces three conventions across 25 call sites: the wrong `(1 items)`, the generated-looking `1 app(s)`, and the same conditional hand-written in each selector. The summary rule width moved into the shared constants too, so the `clean` and `uninstall` summary boxes cannot drift apart.
- The `history` report labels its fields with the shared glyphs and takes a themed header, while the `key=value` text that scripts read stays untouched.
- The single-instance guard raises `LockUnavailable` instead of calling `sys.exit()`, and the router turns it into a `False` return at the point the lock is taken, so one place still converts an outcome into an exit code — the same code 1 as before.
- That refusal, and a failed sudo authorization, now go to stderr. A refusal is not part of the report, so `topo clean > file` leaves the file empty rather than collecting it.
- One `print_action_cancelled()` sentence covers the four paths that can cancel an action, and the sudo prompt rewind is computed from the prompt it actually printed rather than a guessed eight lines.
- Declining the uninstall preview now lands back on the list with the ticks still there and says so, instead of discarding them silently. They are carried by application id, and ids a rescan dropped are discarded before the list is drawn: keeping them inflated the `n/total selected` counter and let Enter return an empty selection, which the screen read as an ESC and quit on.
- Enter with nothing ticked raises a notice rather than quietly acting on the row under the cursor.
- Switching the uninstall sort key no longer reverses the order along with it; each key keeps its own natural direction, and a repeat press is what flips it.
- The confirmation prompt spells out the keys it answers, and `ESC` is cyan wherever it appears — green carries on, cyan leaves.
- The Analyze footer is packed to the terminal's real width: one row wherever the hints fit, evenly split when they do not, and never cut off. It had been two rows by construction, which spent a second line even on the wide terminals where everything fit on one.

### 7. Install and Repository Hygiene
- `install.sh` shipped `tach.toml` into `~/.topo` on every install. Nothing there reads it — it configures `tach check`, which only the local gate script runs — so it joined the cleanup list, and the blacklist test now names it, so removing it fails rather than silently shipping the file again. The stray trailing `\` it arrived with is gone too: it would have swallowed the next entry appended below it.
- The dated review reports under `docs/` are working notes for one round each, already superseded by the commits they describe. They are now ignored by name rather than by a `docs/*.md` glob, which would have hidden a genuinely new tracked document.

---

## Verification
- The full local gate passes: Ruff (lint and format), Mypy with `--check-untyped-defs`, Tach, Vulture, ShellCheck, Clippy, pytest and cargo test.
- 887 Python tests pass, 29 of them added in this range.
- Measured on a real pty and on a redirected run: `NO_COLOR=1` leaves the colors empty and `CLEAR_SCREEN` intact, while `> log` leaves zero escape sequences — not even a stray `\r`.
- `topo analyze | cat` exits 1 with an empty stdout and the reason on stderr, and touches neither the lock nor the command it was asked for.
- An interrupted `clean` prints its per-group results and its summary, closes its audit-log session, and `topo history` renders that session as interrupted rather than incomplete.

# Topo v1.1.4 中文发布说明

Topo v1.1.4 关注的是「没人盯着屏幕时 Topo 在做什么」：重定向或管道运行不再去驱动一个并不存在的终端；被中断的运行会保住它已经删掉了什么的记录；Analyze 终于会报告删除结果，而不是只留下一声提示音。在此基础上，各界面上各自长出来的字形、计数、取消措辞与按键提示，现在统一为同一套词汇。

---

## 主要更新

### 1. 没有终端时的正确行为
- `setup_color_mode()` 在非 TTY 下清空了颜色常量，却保留了 `CLEAR_SCREEN`、`CLEAR_LINE` 和 `ERASE_BELOW`，于是重定向的运行「丢了颜色、留了光标控制」。实测 `topo optimize --dry-run > log`：1510 字节，含 27 段转义序列和 13 帧动画，开头就是 `\033[2J`；现在是 805 字节，零转义。
- 终端控制的开关刻意比颜色的更窄：只看 `isatty()`，不看 `--no-color` 和 `NO_COLOR`。后两者要求的是别上色，而不是别原地重绘画面。
- `terminal_state._write()` 是该模块所有转义序列的唯一出口，因此在这里设防也一并覆盖了进入备用屏幕、隐藏光标和鼠标追踪。此前重定向运行时按 Ctrl-C 会把整套复位序列（鼠标关闭 ×4、光标恢复、图形属性重置、退出备用屏幕）连同一个 `\033[2J` 一起写出去，现在一个都不会有。
- 没有光标可回卷时，进度动画直接跳过线程启动：重定向运行只失去动画，别的什么都不少。
- 交互守卫此前只问「stdin 是不是键盘」，于是 `topo analyze | cat` 一路畅通：选择器照样响应按键，整个备用屏幕的画面顺着管道流走，而用户在盲开一个会删磁盘的工具——并且退出码还是 0。「能不能读到按键」和「有没有人看得见我们画的东西」是两个问题，现在两个都必须为是。

### 2. 中断也要留下记录
- 在 `clean` 或 `uninstall` 中途按 Ctrl-C，此前会把已经做完的那部分报告整个丢掉：分组输出仍缓存在 `redirect_stdout` 里，汇总从未执行，审计日志也没有收到收尾行。现在每一步报告都从 `finally` 中执行，每个分组会把自己已经打印的内容刷出去。
- 「这次运行是否完成」由「走完所有分组的那一条路径」上的标记决定，而不是靠捕获 `KeyboardInterrupt`：SIGTERM 以 `SystemExit` 抵达，任务本身也可能直接抛错，这两者都不该被记为 `ended`。
- `record_history_session()` 原先只放行 `started`/`ended`，`interrupted` 被静默丢弃。现在解析器在两种终止状态下都会闭合会话，并标记为 `⚠ interrupted`；没有收尾行的会话仍显示 `incomplete`，而这个词现在名副其实。
- 卸载的逐项结果同样从自己的 `finally` 输出，标题为 `Uninstall interrupted`，并补上一句「上面没列出的都未被改动」。
- 中断不再清屏。清屏恰好擦掉了中断最有价值的那部分记录——已删除项的 `✓` 行，以及它们下面的滚屏历史。这段代码执行时终端早已复位；真正该擦掉的是半行动画，那是 `CLEAR_LINE` 的活。

### 3. Analyze 会报告删除结果
- 删除成功此前完全没有反馈，只有一声提示音——而笔记本静音或走 ssh 时它是无声的；失败信息直接打到终端，又在同一拍被整屏重绘覆盖。扫描失败的分支也是同样的问题，靠一个 1.5 秒的 sleep 掩着。
- 删除辅助函数改为返回 `(removed, freed_bytes, problem)`，批量删除返回 `DeleteOutcome` 而不再自行打印，因此界面可以把结果渲染成一行提示，**随下一帧一起**出现。
- 提示被限制为一行：画面是绝对定位的，一行折行会把它下面每一行都往下推，直到下一次整屏重绘。每条提示自带字形，不再统一加一个黄色 `⚠` 前缀——删除成功不该被标成警告。

### 4. 统一的字形词汇
- 此前每处都在自己造词：完成是 `✓`、`✔`、`✅` 或手工上色的 `✓`；失败是 `✗` 或 `❌`（仅 `update.py` 就有 28 处）；同一屏上的小标题和等待按键的提示都以 `➔` 开头。
- 值得区分的状态有六种，现在就是六个常量：`OK`（已完成）、`FAIL`（试过但没成）、`WARN`（需要注意但不是失败）、`INFO`（补充说明）、`SKIP`（存在，但本次没动它）、`NA`（这台机器上没有，因此无事可做）。后两者不可互换：该用 `NA` 的地方用 `SKIP`，等于声称「做过一次选择」，而其实没什么可选。
- 最麻烦的是 emoji 形态：`✅` / `❌` / `⚠️` 是双宽字符，混在窄字形的列里会把后面每个字段右推一格——这正是每个 emoji 处都带着一个手工微调的额外空格的原因，而 `doctor` 的行仍然会错位。现在所有字形都是单列宽，并各自携带颜色与复位，因此后面的句子保持无色。
- 引导符号是三个而不是两个：`➤` 表示小标题，`➔` 表示这一行在等你，`●` 表示补充说明。把小标题并进 `➔`，会让 `topo clean` 的四个分组标题读起来像四个提问。列表内的 `•` 仍是第四种，`☉` 则彻底移除。
- 两个测试专门守住这套安排最容易犯的错：新加的字形若忘了登记到颜色名表里，会在 `--no-color` 下继续吐转义序列，而且是静默的——因为同一行上其它字形都很听话；另一个则钉住各列所依赖的单列宽度。

### 5. 预览要看起来像预览
- `clean --dry-run` 用的是和真删除同一个绿色 `✓`。`✓ npm cache (9.3 KiB) would be cleaned` 与 `✓ Cleaned npm cache (9.3 KiB)` 之间只差一个时态——这恰好是读者扫过 40 行报告时最抓不住的差别，而且它既过不了 `--no-color`，也过不了「剥掉转义序列后粘进 issue」。
- `clean` 的 31 行报告现在在预览时统一使用 `SKIP`，与 `optimize` 早已采用的做法一致。其中 21 行位于 `if dry_run:` 内，直接取该字形；另外 10 行两种模式都会打印，改为把字形和时态作为同一个元组一起选定——这才是真正的修复：分开决定，正是 `✓ … would be cleaned` 得以存在的原因。
- 与 `optimize` 不同，这里不把整行变灰：在那边，跳过的是一堆已完成行中的一行，变灰能让它后退；而预览模式下每一行都是预览，全部变灰既没有强调任何东西，还把读者真正要看的文字给暗掉了。
- 有两行保持原样：汇总本来就区分时态；僵尸进程那行保留 `detected`，因为 Topo 只是给父进程发信号，写成 `would be reaped` 会承诺真实运行并不交付的事。
- 这类问题的复发路径是「从现有清理器里复制一行」，而这是静态的，所以测试是一次源码扫描：任何一行都不得同时带有 `OK` 与 `would`；它还断言自己匹配到了二十处以上，因为什么都没找到的扫描同样会静静通过。

### 6. 一致的计数、拒绝与选择
- 一个 `plural()` 辅助函数取代了 25 处调用点上的三种写法：错误的 `(1 items)`、像机器生成的 `1 app(s)`，以及在每个选择器里各自手写的同一段条件判断。汇总分隔线的宽度也移入公共常量，使 `clean` 与 `uninstall` 的汇总框不会各自漂移。
- `history` 报告的字段改用统一字形标注，并采用主题化的标题行；而供脚本读取的 `key=value` 文本保持不变。
- 单实例守卫改为抛出 `LockUnavailable`，不再调用 `sys.exit()`；路由在获取锁的那一处把它转成 `False` 返回，于是仍然只有一个地方把「结果」转换成退出码——退出码依旧是 1。
- 这条拒绝信息，以及 sudo 授权失败，现在都走 stderr。拒绝不属于报告内容，因此 `topo clean > file` 得到的是一个空文件，而不是把拒绝信息收进去。
- 四条可以取消操作的路径，现在共用 `print_action_cancelled()` 的同一句话；sudo 提示的回卷行数按实际打印的提示计算，而不再是猜出来的八行。
- 在卸载预览里选择放弃，现在会带着仍然勾选的条目回到列表，并明确说明这一点，而不是静默丢弃。勾选按应用 id 保存，并在绘制列表前剔除重新扫描后已不存在的 id：留着它们会让 `n/total selected` 计数虚高，还会让 Enter 返回一个空选择，而界面会把空选择当成 ESC 直接退出。
- 没有勾选任何条目时按 Enter 会给出提示，而不是悄悄对光标所在的那一行动手。
- 切换卸载排序键不再顺带反转顺序；每个排序键保持自己天然的方向，反转交给「再按一次同一个键」。
- 确认提示会写清自己接受哪些按键；`ESC` 在所有出现的位置都是青色——绿色表示继续，青色表示离开。
- Analyze 的页脚按终端实际宽度排布：装得下就一行，装不下就均匀分成多行，且永不被截断。此前它按构造固定为两行，即使在完全装得下的宽终端上也要占掉第二行。

### 7. 安装与仓库整洁
- `install.sh` 每次安装都会把 `tach.toml` 一起装进 `~/.topo`。那里没有任何东西会读它——它配置的是 `tach check`，而只有本地门禁脚本会运行——因此它进入了清理列表；黑名单测试现在也点名了它，把它从列表里删掉会导致测试失败，而不是又一次静默地装进去。它原先带着的那个多余的续行反斜杠也一并去掉：它会把后面新追加的条目一起吞掉。
- `docs/` 下按日期命名的评审报告，是每一轮评审的工作笔记，其结论已由它们所描述的提交取代。现在按文件名逐条忽略，而不是用 `docs/*.md` 通配——后者会把真正新增的受版本控制的文档一起藏起来。

## 验证
- 本地完整门禁全部通过：Ruff（检查与格式）、带 `--check-untyped-defs` 的 Mypy、Tach、Vulture、ShellCheck、Clippy、pytest 与 cargo test。
- 887 个 Python 测试通过，其中 29 个是本次区间新增的。
- 在真实 pty 与重定向运行下分别实测：`NO_COLOR=1` 时颜色为空而 `CLEAR_SCREEN` 保持有效；`> log` 输出零转义序列，连一个多余的 `\r` 都没有。
- `topo analyze | cat` 以退出码 1 结束，stdout 为空，原因写在 stderr；既不会去取锁，也不会执行被请求的命令。
- 被中断的 `clean` 会打印各分组结果与汇总、闭合自己的审计日志会话，`topo history` 会把该会话显示为 interrupted，而不是 incomplete。
