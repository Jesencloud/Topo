# Topo v1.1.6

Topo v1.1.6 is primarily a maintainability and architecture release. It separates the uninstall pipeline into explicit read-only and destructive stages, replaces informal dictionary and string contracts with checked types, and turns several long command flows into named operations whose dependencies are enforced by Tach. It also improves installer resilience on unstable TLS connections and closes several correctness issues uncovered while making those boundaries explicit.

---

## Highlights

### 1. More Resilient Release Downloads
- Release downloads now share one curl retry policy instead of repeating flags at five call sites.
- On curl 7.71 and newer, the installer enables `--retry-all-errors`, allowing interrupted TLS handshakes and other errors outside curl's default transient-error set to be retried.
- Older curl versions remain supported through capability detection: Topo omits the unsupported option instead of failing before a download begins.
- The signed manifest, signature, public key, source archive, and Rust engine all use the same tested retry policy without weakening checksum or GPG verification.

### 2. Uninstall Pipeline Split by Responsibility
- Replaced the former 1,949-line `src/uninstall.py` module with a focused package: `discovery`, `manager`, `residue`, `collateral`, `processes`, `removal`, and `names`.
- App discovery is now explicitly read-only and independent from removal. The manager owns scan caching and size aggregation, while the interactive screen composes discovery, process termination, package removal, and residue deletion in order.
- Residue detection cannot import or invoke deletion logic; it only identifies candidate paths and passes them to the removal stage. Tach enforces this one-way dependency.
- Package removal, process termination, collateral-package previews, residue matching, and scan fan-out each have a single module owner, reducing the chance that a change in one path silently affects another.

### 3. Checked Data Contracts and Single Sources of Truth
- Installed applications now use `TypedDict` records that distinguish required scan fields from optional computed fields. Missing required keys and misspelled keys are caught by Mypy instead of failing later at runtime.
- Uninstall results use a typed `UninstallOutcome`, ensuring every removal path returns the same success, reclaimed-space, and error contract.
- The eight package types are defined once by `AppType`, replacing 31 duplicated string literals across discovery, removal, package-manager metadata, and UI privilege decisions.
- Shared terminal widths, duration units, protected cache names, and archive suffixes are now named once rather than re-derived or copied across call sites. Structural tests prevent these definitions from drifting back into literals.

### 4. Clearer Analyze and Command Flows
- The Analyze navigation stack is represented by a typed view record, preserving page and cursor position explicitly when entering a directory and returning to its parent.
- The 337-line deep-analysis loop is reduced to a screen-oriented control flow supported by named helpers for scanning, row construction, category and insight assembly, selection deletion, and open-file reporting.
- Doctor, Status, launcher installation, registered application cleaning, and residue discovery are similarly split into named stages instead of numbered comment blocks inside long functions.
- Whitelist command handling moved out of `main.py` into `src/manage/whitelist.py`, so the main dispatcher once again delegates every subcommand through a single feature entry point.

### 5. Correctness Fixes Revealed by the Refactor
- One unreadable `.desktop` directory no longer discards application names already collected from other readable directories and package managers.
- Whitelist write failures now return failure instead of being reported as “already present” or “not found”; duplicate and missing entries remain successful no-ops where appropriate.
- The protected-cache list used by orphan cleanup is immutable and covered by a deletion guard, protecting desktop caches such as PulseAudio, fontconfig, and icon themes from the orphan heuristic.
- Analyze's two-column “Selected to Remove” summary now derives its name width from the terminal, preventing rows from wrapping and shifting the screen at ordinary 80-column widths.
- Doctor resolves the Rust engine once and probes the same binary it reports, rather than potentially displaying one candidate and validating another.

---

## Verification
- The full local gate covers Ruff formatting and linting, Mypy, Tach, Vulture, ShellCheck, Clippy, pytest, Cargo tests, and bundled-engine consistency.
- The Python suite includes regression coverage for installer retry capability detection, Analyze drill-down state restoration, unreadable desktop directories, protected cache preservation, whitelist exit codes, uninstall scan caching, and partial scanner failure.
- Structural tests enforce module boundaries, the package-type vocabulary, shared time constants, and the single definitions used by cleanup and terminal layout.
- Behavioral equivalence probes were used throughout the refactor to compare command output, removal commands, scan ordering, filesystem effects, and residue results before and after module extraction.

# Topo v1.1.6 中文发布说明

Topo v1.1.6 以可维护性和架构优化为主线：将卸载流程拆分为明确的只读阶段与删除阶段，用可静态检查的类型取代约定式字典和字符串，并把多个长命令流程整理为具名操作，由 Tach 强制维护依赖方向。同时，本版本增强了不稳定 TLS 网络下的安装可靠性，并修复了在边界梳理过程中发现的多项正确性问题。

---

## 主要更新

### 1. 更可靠的 Release 下载
- 所有 Release 文件下载统一使用一套 curl 重试策略，不再在五个调用点分别重复参数。
- curl 7.71 及以上版本会启用 `--retry-all-errors`，TLS 握手中断等不属于 curl 默认“瞬时错误”的失败现在也能自动重试。
- 通过能力探测兼容旧版 curl：不支持该参数时自动省略，不会在真正下载开始前因未知选项退出。
- 签名清单、签名、公钥、源码归档和 Rust 引擎全部使用同一套经过测试的重试策略，同时保持 SHA256 与 GPG 校验强度不变。

### 2. 按职责拆分卸载流程
- 将原先 1,949 行的 `src/uninstall.py` 拆分为职责明确的 `discovery`、`manager`、`residue`、`collateral`、`processes`、`removal` 与 `names` 模块。
- 应用发现阶段现在明确保持只读，并与删除逻辑解耦；Manager 只负责扫描缓存和大小聚合，交互界面按顺序组合应用发现、进程终止、软件包卸载与残留删除。
- 残留检测模块不能导入或调用删除逻辑，只负责生成候选路径并交给 Removal 阶段处理；这一单向依赖由 Tach 强制检查。
- 软件包卸载、进程终止、关联软件包预览、残留名称匹配和多来源扫描分别拥有唯一模块归属，降低局部修改影响其他路径的风险。

### 3. 类型化数据契约与单一事实来源
- 已安装应用改用 `TypedDict`，明确区分扫描时必有字段与后续计算的可选字段；缺少必填字段或键名拼写错误会由 Mypy 提前发现。
- 卸载结果改用类型化的 `UninstallOutcome`，确保每条删除路径统一返回成功状态、释放空间和错误信息。
- 八种软件包类型统一由 `AppType` 定义，取代应用发现、卸载、包管理器元数据和 UI 提权判断中的 31 处重复字符串。
- 终端列宽、时间单位、受保护缓存名称和压缩包后缀等规则均收敛为单一定义；结构性测试防止后续重新散落为魔法数字或字符串。

### 4. 更清晰的 Analyze 与命令流程
- Analyze 导航栈改为类型化 View 记录，进入子目录再返回时，页码和光标位置成为明确状态，不再依赖未记录完整的字典键约定。
- 原 337 行的深度分析循环缩减为面向界面流程的控制逻辑，扫描、行数据生成、分类与洞察组装、删除选择和文件打开反馈分别由具名函数负责。
- Doctor、Status、启动器安装、应用清理器聚合和残留路径发现也由长函数中的编号注释块拆分为具名阶段。
- Whitelist 命令从 `main.py` 迁入 `src/manage/whitelist.py`，主命令分发器重新做到每个子命令只调用一个功能入口。

### 5. 重构过程中发现的正确性修复
- 单个不可读的 `.desktop` 目录不再导致其他可读目录和包管理器已经收集到的应用名称全部丢失。
- 白名单写入失败现在会正确返回失败，不再被误报为“已经存在”或“未找到”；真正的重复添加与缺失删除仍保持安全的成功空操作。
- 孤立缓存清理使用的保护名单改为不可变集合，并新增删除守卫测试，确保 PulseAudio、fontconfig 和图标主题等桌面缓存不会被孤立目录规则误删。
- Analyze 的双列“Selected to Remove”摘要会根据终端宽度计算名称列，避免在常见 80 列终端中换行并推动后续界面错位。
- Doctor 现在只解析一次 Rust 引擎，并检查它实际展示的同一个二进制，不再可能显示一个候选项却验证另一个。

## 验证
- 本地完整门禁覆盖 Ruff 格式与检查、Mypy、Tach、Vulture、ShellCheck、Clippy、pytest、Cargo tests 以及随包 Rust 引擎一致性。
- Python 测试覆盖安装器重试能力探测、Analyze 深入与返回状态恢复、不可读 desktop 目录、受保护缓存、白名单退出码、卸载扫描缓存以及单个扫描源失败等场景。
- 结构性测试持续约束模块边界、软件包类型词汇、公共时间常量，以及清理规则和终端布局所使用的单一定义。
- 重构期间通过行为等价探针对比前后版本的命令输出、卸载命令、扫描顺序、文件系统结果和残留路径，确保模块拆分不改变既有行为。
