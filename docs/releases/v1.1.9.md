# Topo v1.1.9

Topo v1.1.9 is another correctness-, safety-, and performance-hardening release. It closes the findings of a series of end-to-end reviews completed since v1.1.8: the Rust engine ↔ Python boundary, concurrency/lock/state consistency, the config, whitelist and state files, exit codes and scriptability, and performance on large and networked filesystems. Scans are now controllable and safe on NFS, the Analyze cache no longer shows pre-deletion sizes, `topo clean` and the other commands report real exit codes a script can trust, and the config and whitelist are written owner-only. No behavior a correct run depends on has changed; what changed is what happens on the unhappy paths.

---

## Highlights

### 1. Faster, controllable scanning on large and networked filesystems
- The bundled Rust engine now takes an explicit walk width from `TOPO_SCAN_THREADS`, and topo passes a `TOPO_IO_THREADS` ceiling through to it, so a scan whose target sits on NFS, sshfs or CIFS can be pinned to a serial or low-concurrency walk instead of aiming one `readdir` per core at a single server.
- The engine-less size fallback no longer re-invokes the engine once per descendant directory, so a stale or timed-out engine degrades to a single linear walk rather than a per-directory rescan that scaled with depth.
- Size and freshness are answered from one traversal on the cleanup path, and a deeply nested directory can no longer exhaust the recursion limit mid-clean.
- `--stats` stays on the filesystem it was pointed at, so measuring a directory with a mount under it no longer silently counts another disk.
- A scan that runs out of time says so once, and the single scan timeout is defined in one place.

### 2. Trustworthy Analyze cache
- Deleting from Analyze now invalidates the cached size of every parent directory, so stepping back out of a folder shows the new total instead of the pre-deletion one.
- A cache entry has a maximum age, so a change made deep inside a tree by something other than topo is re-measured rather than served stale for the life of the process.

### 3. Dependable exit codes for scripts and CI
- `topo clean` exits non-zero when a command-level cleanup actually fails, instead of reporting success for a package-manager clean that returned an error.
- A closed output pipe (`topo history | head`) exits quietly with 141 rather than printing a `BrokenPipeError` traceback.
- The exit-code contract is written down: 0 success (including "nothing to do"), 1 failure/refusal/cancellation, 2 argument error, 130 SIGINT, 143 SIGTERM, 141 closed pipe. Failures and the interrupt notice go to stderr, so a redirected report collects only the report.
- `topo history --limit` rejects zero or a negative count with exit 2 instead of silently treating it as 1.
- `topo doctor`'s green exit is documented as "topo itself is healthy", not "every command will run" — a missing curl/gpg still blocks `topo update` and is flagged, not counted as a failure.

### 4. Private, resilient config, whitelist and state files
- The whitelist and config are written owner-only (0600) in an owner-only (0700) config directory, matching the audit log, so another local user can no longer read which paths you have chosen to protect.
- An unreadable config warns instead of silently dropping a `min_age_days` floor that would widen a cleanup; migration is gated on the stored version being behind the current one, so a future format change actually runs; and an absurd `min_age_days` is capped rather than crashing every age-gated cleanup.
- Topo's one JSON reader/writer bounds how much it reads, treats the full set of serialization errors as a failed write rather than only `OSError`, gives every atomic write its own scratch file, and reaps a crashed write's leftover scratch; the never-rotated deletion log is read bounded, and a corrupt negative size is clamped.
- `topo doctor` reports the mode of the config directory, whitelist and config file, and lists any config keys topo does not recognize.

### 5. A runtime-checked Rust engine boundary
- The engine wraps every mode's JSON output in a versioned `{schema_version, data}` envelope; Python (and doctor's probe) validate the version and fall back to the pure-Python walk on a mismatch, so a stale or foreign engine binary is detected at runtime instead of silently misread — and the first such refusal turns the engine off for the rest of the run and says so once.
- A write failure inside the engine exits non-zero instead of being swallowed as a successful empty scan; `--min-bytes` parsing no longer mistakes a directory named `--min-bytes` for the flag.
- A running `clean` now picks up a whitelist change made by another process; Ctrl-C no longer runs the optimize/analyze tasks that were queued but had not started; and a dead package-manager source during app discovery is surfaced as a warning rather than silently shrinking the list.

---

## Verification
- The Python suite contains 1,188 tests and runs on Python 3.10 and 3.14 in CI.
- CI enforces Ruff linting and formatting, Mypy including untyped function bodies, Tach module boundaries, Vulture dead-code checks, ShellCheck, Cargo Clippy/formatting, and 22 Rust unit and integration tests.
- Both bundled musl engines are checked against `topo-core/engine.stamp` and against a fresh build of the current Rust source, so a committed binary cannot drift from the source it claims to come from.
- Release jobs build x86_64 and aarch64 static musl engines plus DEB and RPM packages, then smoke-test script installation, package installation/removal, multiple Linux distributions, and ARM64 execution under QEMU.
- Every published installer, source archive, engine, and package is covered by `SHA256SUMS`; the manifest is signed with the project release key before the GitHub Release is created.

# Topo v1.1.9 中文发布说明

Topo v1.1.9 又是一次以正确性、安全性和性能加固为主的版本。它落实了自 v1.1.8 以来一系列端到端审查的结论：Rust engine ↔ Python 边界、并发/锁/状态一致性、配置与白名单及状态文件、返回码与脚本可用性，以及大规模与网络文件系统上的性能。现在扫描在 NFS 上可控且安全，Analyze 缓存不再显示删除前的旧尺寸，`topo clean` 等命令返回脚本可信的真实退出码，配置与白名单以仅属主可读写入。正确运行所依赖的行为没有任何改变；改变的是出错路径上会发生什么。

---

## 主要更新

### 1. 大规模与网络文件系统上更快、可控的扫描
- 内置 Rust engine 现在从 `TOPO_SCAN_THREADS` 取明确的遍历宽度，topo 还会把 `TOPO_IO_THREADS` 上限传递给它；因此目标位于 NFS、sshfs 或 CIFS 上的扫描可以被固定为串行或低并发遍历，而不是对单台服务器发起每核一个 `readdir`。
- 无 engine 时的尺寸回退不再对每个后代目录重新调用 engine，因此一个陈旧或超时的 engine 会退化为一次线性遍历，而非随深度放大的逐目录重扫。
- 清理路径上，尺寸与新鲜度由同一次遍历得出；深度嵌套的目录不再会在清理途中耗尽递归上限。
- `--stats` 只停留在它被指向的那个文件系统上，所以测量一个下面挂载了其它设备的目录时，不会再悄悄把另一块盘算进去。
- 扫描超时会提示一次，且单一的扫描超时只定义在一处。

### 2. 可信的 Analyze 缓存
- 从 Analyze 删除时，现在会使每一级父目录的缓存尺寸失效，所以退回上一层看到的是新的总量，而不是删除前的旧值。
- 缓存条目有最长存活时间，因此由 topo 以外的东西在目录树深处造成的改动会被重新测量，而不是在整个进程生命周期内一直返回陈旧值。

### 3. 面向脚本与 CI 的可靠退出码
- 当某个命令级清理确实失败时，`topo clean` 以非零退出，而不再把一个返回错误的包管理器清理报告为成功。
- 输出管道被提前关闭（`topo history | head`）时安静地以 141 退出，而不是打印 `BrokenPipeError` 回溯。
- 退出码约定被写下：0 成功（含“无事可做”），1 失败/拒绝/取消，2 参数错误，130 SIGINT，143 SIGTERM，141 管道关闭。失败与中断提示走 stderr，所以重定向的报告里只会收集到报告本身。
- `topo history --limit` 对 0 或负数以 2 退出，而不再悄悄当作 1。
- `topo doctor` 的绿色退出被明确为“topo 自身健康”，而非“每条命令都能跑”——缺少 curl/gpg 仍会挡住 `topo update`，并被标注而非计为失败。

### 4. 私密、健壮的配置、白名单与状态文件
- 白名单与配置以仅属主可读写（0600）写入仅属主可访问（0700）的配置目录，与审计日志一致，因此同机其他用户无法再读到你选择保护了哪些路径。
- 配置不可读时会告警，而不是悄悄丢弃一个会放宽清理的 `min_age_days` 下限；迁移以“存储版本落后于当前版本”为闸门，使将来的格式变更确实会执行；荒唐的 `min_age_days` 会被夹到上界，而不是让每一次带年龄门的清理崩溃。
- topo 唯一的 JSON 读写器会限制读取量，把整套序列化错误（而非仅 `OSError`）都当作写入失败，为每次原子写入分配各自的临时文件，并回收崩溃写入残留的临时文件；从不轮转的删除日志以有界方式读取，损坏的负数尺寸被夹到 0。
- `topo doctor` 会报告配置目录、白名单与配置文件的权限位，并列出 topo 不认识的配置键。

### 5. 运行时校验的 Rust engine 边界
- engine 把每种模式的 JSON 输出包进带版本的 `{schema_version, data}` 信封；Python（以及 doctor 的探测）校验版本，不匹配时回退到纯 Python 遍历，因此陈旧或外来的 engine 二进制会在运行时被发现而非被静默误读——而且第一次这样的拒绝会在本次运行剩余时间内关闭 engine 并提示一次。
- engine 内部的写入失败以非零退出，而不是被当作一次成功的空扫描吞掉；`--min-bytes` 的解析不再把一个名为 `--min-bytes` 的目录误当成该参数。
- 正在运行的 `clean` 现在会读到另一个进程对白名单做的改动；Ctrl-C 不再把已入队但尚未开始的 optimize/analyze 任务跑完；应用发现期间某个失效的包管理器来源会作为警告呈现，而不是悄悄缩短列表。

## 验证
- Python 测试套件包含 1,188 项测试，并在 CI 中覆盖 Python 3.10 与 3.14。
- CI 持续检查 Ruff lint/format、包含未注解函数体的 Mypy、Tach 模块边界、Vulture 死代码、ShellCheck、Cargo Clippy/format 以及 22 项 Rust 单元与集成测试。
- 两个内置 musl engine 都会与 `topo-core/engine.stamp` 以及当前 Rust 源码的全新构建对照，使已提交的二进制无法与它声称来源的源码发生漂移。
- Release 工作流构建 x86_64 与 aarch64 静态 musl engine、DEB 和 RPM，并验证脚本安装、系统包安装与移除、多种 Linux 发行版及 QEMU 下的 ARM64 执行。
- 发布的 installer、源码归档、engine 与系统包全部纳入 `SHA256SUMS`；GitHub Release 创建前会使用项目发布密钥对清单签名。
